## Task 1 — `eight_workers_plan_while_tokio_inserts_and_invalidates` deterministic under R1
Evidence: Linux CI printed `stress: 8000 pages in 433 ms, 154 invalidations … 0 two-call pages` and the ruled guard `0 < jobs_calls` (ruling d06b3a09; Mellow non-blocker #1 in b82ca453 predicted this) panicked at `single_roundtrip.rs:517`. On a fast 2-core runner no route reached a 64 all-hit streak between 1 ms invalidations, so no route ever stopped offering and the two-call path never ran.
Fix (Mellow's proposal, accepted): give the invalidator a deterministic quiet window — phase 1: run ≥ 64 all-hit pages per route (e.g. the first `64 × routes` pages, or the first 25% of pages) with the invalidator PAUSED (an `AtomicBool` the invalidator thread checks), so every route provably stops offering (assert via the `plan_offer`-style signal if cheap, otherwise by construction); phase 2: resume the 1 ms invalidations for the rest, so tokio-side misses on non-offering routes are guaranteed → `jobs_calls > 0`. Keep every other assertion byte-identical (`loader_calls == pages`, `worker_calls == pages + jobs_calls`, bodies). Do NOT drop or weaken the guard. Mutation check: with phase 1 removed the test must fail on your machine at least under `taskset`/reduced parallelism or by forcing `OFFER_STOP` unreachable — note how you checked. Run `cargo test -p brust-server --test single_roundtrip` ×10 debug and ×3 `--release`.
