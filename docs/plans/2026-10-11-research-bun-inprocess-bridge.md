# Research spike — can brust-server live in-process with Bun's (now mostly Rust) runtime?

owner: 22499151-e133-4508-b358-d7fa4d2851c3 (Detoro) · authority: in-loop · tier: research · role: Researcher (Guetta) · read-only: NO code changes in any brust branch; Bun checkout at ~/code/bun may be `git fetch`ed and inspected on a detached HEAD only.

## Why
nylon-ring (github.com/AssetsArt/nylon-ring) shows native↔native in-process RPC at ~40 ns per unary call and a 1.9 ns FFI boundary. brust's Rust↔Bun bridge costs ~15 µs per round trip (thread hop via napi tsfn + JSON in both directions; `bench/ATTRIBUTION.md` "After P7": bridge ≈ 21% of I at c=1, loader-response parse 81 µs ≈ 16% of D). Zero-copy over the existing boundary was tried three ways and rejected with evidence (see workspace memory "ssr multirender zerocopy research": SAB request corruption, napi-Buffer object churn crash, nylon-ring pointer transfer impossible across a JS isolate). The only structural way to remove that cost is to make the HTTP thread and the JS isolate thread the SAME thread in the SAME process, calling JS through Bun's own Rust host layer instead of napi. Bun's source is now majority Rust (~/code/bun @91270aa, 2026-06-04: 970k Rust lines vs 665k Zig; `src/runtime/{dispatch_js2native.rs, generated_host_exports.rs, http_jsc, uws_sys}`), which is what makes this question worth asking now.

## Questions (answer each with file:line evidence from the CURRENT Bun main branch)
1. **Embedding surface.** Does Bun build as a library (staticlib/cdylib, `bun_bin` vs a lib crate), or expose any in-process extension point for native code that runs on the isolate thread with access to the js2native/host-exports layer (not napi)? Include: how `bun:ffi` `JSCallback` is implemented and its threading rules; whether a Bun native module (the Rust `runtime` crates) could host a hyper server on the isolate thread or run an isolate on a hyper thread.
2. **Calling JS from Rust on the isolate thread.** Which primitive(s) call a JS function synchronously from Rust inside Bun (JSC API bindings in Rust: `JSValue`, `JSFunction::call`, `JSPromise`), what they cost (find Bun's own micro-benchmarks or estimate from the generated bindings), and how async results (Promise) are awaited without leaving the thread.
3. **Values without JSON.** Can Rust build a JS object/array/string directly (JSC API: `JSObject::put`, `JSString::from_utf8`, typed arrays over Rust memory) and read a JS object's fields back without `JSON.stringify`? What does Bun use for its own structured data crossing (e.g. `http_jsc` request objects)?
4. **Build and maintenance cost.** What would brust-server have to link (Zig runtime, JSC/WebKit, Bun's Rust crates) and with which toolchains; how stable are these internals across Bun releases (compare 2026-06 vs now); what patch surface we already carry for the compiler crates (`docs/design/2026-10-08-react-compiler-design.md` spike report, 44-line HIR patch) and how it would grow.
