## Contracts between lanes (the only cross-lane facts; each is also in the owning plan)

1. **Manifest JSON** — spec S6 **plus its 2026-10-09 amendments** (inputs relative to props; `per_instance` = list context path; `children[].props` map with `[idx]`; `children[].instances` is the STRING form `"static" | "per-row:<list path>"`, `k` derived from order on both sides, never on the wire; **react children are parent jobs with `outputs[]`, not child records; `"*"` = all props; per-component overlays; scoped `cache({key})`** — S6 amendments of 2026-10-09 on Mellow's challenge f4649e5d) is the schema. `m2a` produces the IR fields it is built from
   (`uses_outlet`, `use_id_slots`, `instances[]`, `jobs[].{kind,inputs,per_item}`, `cache`,
   `client_props`, `children[]`); `m2b` parses the schema from hand-written fixtures; `m2c`
   writes it from the IR. If `m2a`'s IR and S6 disagree, S6 is amended by the lead (challenge on
   either task), never patched around in `m2c`.
2. **Island host** — `<brust-island data-id="<componentId>" x-props='<json>'>…</brust-island>`
   (`m2a` emits, `m2b` fills `_ssr_<id>` inside, `m2d` hydrates). Attribute names are fixed here.
3. **Island chunk protocol** — `(globalThis.__brustIslands ||= []).push([id, hydrate]); globalThis.__brustIslandReady?.()`
   (`m2d` consumes, `m2c` generates the shim). Hydrated hosts carry `data-hydrated="1"`.
4. **`useId`** — the k-th `useId()` of a component reads context value `_id{k}` (array under a
   per-item scope); the server allocates `brust-<routeId>-<instance>-<k>` (`m2a` seeds the template
   and `x-props`, `m2b` allocates).
5. **Outlet** — `{{ __outlet | safe }}` in the layout template; the server renders the chain
   leaf-first (`m2a` emits, `m2b` composes). `outlet-outside-layout` is raised by `m2c` at build
   from `uses_outlet` + the route tree (S8 amendment: the compiler cannot see the route tree).
6. **Document root** — `<html>` is an ordinary host element; the client bootstrap mounts from
   `document.documentElement` (`m2a` fixture `document-root` proves it, `m2c` bootstrap does it).
7. **Bun call shapes** — `CallKind::{Loader, Jobs}` with the request/response JSON of spec S1
   (`m2b` defines the Rust structs and the `RenderDispatch` trait; `m2c` implements the napi
   `TsfnDispatch` and the worker-side handlers).
8. **napi surface** (names `m2c` must export; `m2b` exposes the Rust functions they wrap):
   `brust_server::start(Config) -> Handle`, `Handle::shutdown(drain_ms)`, `invalidate(InvalidateArgs)`,
   `stats() -> StatsJson`, `register_dispatch(impl RenderDispatch)`.

9. **Diagnostics raised at lowering** — `nested-instance` and `outlet-in-react` (and any
   lowering-time Error) are NOT in `--emit ir` output; the build lane (`m2c`) must compile every
   component through lowering (`--emit all` / the napi `compileFile` running `compile_tree`) and
   treat a non-zero result as a build error. An IR-only pass is never a build.

## Decisions for wave 3 (`m2e-pokedex-exit`), ruled 2026-10-09 before its plan is written

- **Offline dataset.** 0.1.x pokedex loaders fetch live PokeAPI (`lib/pokeapi.ts`, `API = https://pokeapi.co/api/v2`). The v2 port ships a committed JSON snapshot `examples/pokedex/data/pokedex.json` (first 151 Pokémon: id, name, types, stats, artwork URL, species flavour/genus, evolution chain; the 18 type relations) generated once by `examples/pokedex/scripts/snapshot.ts` (network, run by hand, output committed). Loaders read the snapshot; no network at runtime, so e2e and bench are deterministic and CI needs no egress.
- **Components become hooks.** `ThemeToggle` = `useState` + `useEffect` setting `document.documentElement.dataset.mode` (no cookie write; actions are M3; the loader still reads `req.cookies.mode` for first paint). `HeroSearch` = controlled input whose form GETs `/pokedex?q=` (no SPA navigate). `DexFilter` = `useState` filter/sort over a keyed list of `<DexCard>` rows (per-row child props). `NavLink` = static `<a>` with the active class computed in the loader (`path`). `Breadcrumb` = static. `TeamBuilder` = react tier on purpose: `useReducer` roster seeded from `teamInitial`, add/remove local only (no store, no actions); `AddToTeamButton` dropped. `TypeChart` unchanged (also the F32 `<table>`-free grid). `AppLayout` returns `<html>…<Outlet/>…</html>` (no `BrustPage`).
- **Styling.** `app.css` (692 B, Tailwind v4 `@import`) is replaced by a prebuilt static `public/app.css` generated once with the Tailwind CLI and committed; no CSS modules; no CSS pipeline in M2.
- **Chromium.** The repo has no Playwright. m2e adds `playwright` (+ `npx playwright install chromium` in the CI `server` job) for ONE test: open `/pokemon/pikachu`, wait for `brust-island[data-hydrated="1"]`, assert no console errors and that the `TeamBuilder` button toggles the panel. Everything else is `fetch`-based like 0.1.x `tests/integration.test.ts` (freePort / readPortLine / SIGINT pattern).
- **Bench.** Port `scripts/benchmark.ts` (oha, `BENCH_CONN`/`BENCH_DUR`/`BENCH_WARMUP`) with three probes on BOTH apps: static hit (`/type-chart` second request), native miss (`/pokemon/{name}` with a varying name = loader + job), react child (`/` renders TeamBuilder). The 0.1.x side runs `example/pokedex` from `main` built release. Bar: v2 not slower on any probe; report `bench/RESULTS.md` + JSON, deltas, host, Bun version.
- **Release dry run.** v2 `release.yml` = the 0.1.x matrix (6 targets, zig cross legs) building `crates/brust-napi` into `packages/brust/native`, `napi artifacts` + `npm publish --dry-run` for `@brust/core`, `@brust/runtime-dom`, `@brust/native-<plat>` under `workflow_dispatch`; the real publish job stays tag-gated and is a human action. `scripts/release-bump.ts` ported to bump every `@brust/*` version reference atomically.
- **Exit report.** `docs/plans/m2-exit-report.md` generated by the e2e suite from pinned sets (routes, probes, closed ledger rows), diffed in CI like the M1 reports.

## Standing process rules for M2 (inherited from M1, restated once)

- Lanes are created by the lead from `v2` with `git worktree add ../brust-lane-<slug> -b lane/<slug> v2`;
  implementers `task claim`, never `lane start` (it branches from `main`). Teardown is by hand.
- Task state chain: `claimed → in_progress → review → merged` (the lead runs the last two after
  `MERGE-READY`).
- Gate runner tells the Coordinator after every run; the Coordinator dispatches reviewer and gates
  in parallel on `READY`; `MERGE-READY <slug> @<sha>` goes to the lead; the lead merges after PR
  CI is green on all jobs (never before — anomaly PR #95), then `task state merged`.
- Reviewer bar (unchanged): a blocker is "silently wrong output with no diagnostic"; negative
  controls are RUN, not read.
- Challenges go on the task (`task challenge`), the lead rules on the task (`task rule`) and amends
  the spec/plan; a ruling that exists only in a tell is copied to the record before close.
- Generated reports (`docs/react-coverage.md`, `docs/plans/m1-exit-report.md`, later
  `docs/plans/m2-exit-report.md`) are never hand-edited; CI diffs them.
