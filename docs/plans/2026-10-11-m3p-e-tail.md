**Goal:** Land lever P7 of the M3-P spec as three lanes from `m3p` @ 2ca941d. The levers come from the post-P6 tree in `bench/ATTRIBUTION.md`, which found the §5 stop rule NOT met (D 18.2% inherent, I 62.7%; only one lever, P6, came in under 2%). F68 is NOT met on I in today's A/B: median D +7.7%, I −2.4%. P7 targets the largest non-inherent costs:
- **D:** the leaf template render (287 µs of a 546 µs request at c=1) and the loader-response parse (88 µs).
- **I:** about 5 µs of CPU per request that v2 spends beyond 0.1.x (55.3 against 50.0 µs). This host runs near saturation with the server and oha together, so that CPU gap decides I. Its sources are process-global locks and timers taken on every request (39% of tokio wall samples on I are blocked in `__psynch_mutexwait`), plus P6's plan offer on an all-hit page.

Every rendered byte and header stays identical.

**Architecture:** Three lanes with disjoint files. Each lever was measured on a prototype before this plan was written (Evidence).
1. **`m3p-e-template-lowering`** (compiler + brust-jinja). The compiler stops emitting `{% set _iN = loop.index0 %}` when nothing in the row reads `_iN`. It lowers a literal style object (`{{ {"background": v} | style_css | e }}`) to one `css_decls(...)` function call with the keys known at compile time, so no minijinja dict (a `BTreeMap`) is built per element. Optionally (C4) it prints `t.name` instead of `t["name"]` for identifier-shaped constant keys. On the D template (harness, real data, byte-identical output): render 282 → 193 µs, and 185 µs with C4.
2. **`m3p-e-borrowed-templates`** (render.rs). Templates are registered as `&'static str` (sources leaked once per `Renderer`). `get_template` then reads minijinja's `borrowed_templates` map: no `Mutex`, no `Arc` clone. Today minijinja 3 takes a global `Mutex` and clones an `Arc` for every owned template, twice per request.
3. **`m3p-e-timers`** (server, dispatch, pool, pipeline):
   - (a) hyper's `header_read_timeout` runs on a coarse sharded timer of our own instead of the tokio wheel, which costs one global lock per register and per clear on every request;
   - (b) the loader-call deadline is enforced per slot by one sweeper task instead of a `timeout_at` per request;
   - (c) `claim_or_wait` claims first and registers on `idle_notify` only when every slot is busy;
   - (d) the loader response is parsed with `from_str` after one UTF-8 validation;
   - (e) small shared-cache-line writes go: a static `X-Powered-By`, no per-request `Arc<Server>` clones, the render hint stored only when it changes, the loader/worker counters moved off one shared line;
   - (f) the plan offer becomes adaptive (ruling R1): a route whose planned calls keep coming back all-hit stops being offered the plan, and it is offered again on the first miss.

**Tech Stack:** Rust nightly-2026-09-15, minijinja 3.0.0 (`builtins macros multi_template serde`, no `preserve_order` → dict literals are `BTreeMap`s), hyper 1.12 / hyper-util 0.1.21 (`hyper::rt::Timer`, `auto::Builder`), tokio 1.53.2, parking_lot 0.12, serde_json 1, criterion 0.8, Bun canary, `oha`, macOS `sample`.

## Review Focus

1. **Coarse timer correctness (A2).** `CoarseSleep` must implement `hyper::rt::Sleep` + `Future` (and `reset` through `Timer::reset`). It is Ready iff `Instant::now() >= deadline`; a pending poll registers or refreshes its waker in exactly one shard. Drop and reset unregister it. The ticker wakes every registered entry whose deadline has passed and never holds a shard lock while calling `wake()`. The ticker is spawned once per server, and drain/shutdown stops it. Pinned by `tests/coarse_timer.rs` (fires within deadline + 2 ticks; a dropped sleep never wakes; reset to a later deadline does not fire early; 8 threads × 10,000 register/drop with no leaked entries: `CoarseTimer::registered() == 0`) and by the unchanged `http_hygiene::partial_request_headers_time_out`.
2. **Deadline sweeper and the claim invariant (A3).** The slot's deadline cell is armed only while a `RenderClaim` is held, and it is disarmed in `RenderClaim::drop` (the pool.rs INVARIANT: a slot is not released before its Promise settles). A deadline that fires makes `call_worker_planned` return `CallError::Deadline` and detaches the remainder exactly as the `timeout_at` branch does today. It never releases the claim early. The jobs-phase extension reads `jobs_phase_since` as today. Pinned by `tests/busy.rs` and `single_roundtrip.rs`'s per-phase deadline test (both unchanged, tolerances included; if a tolerance is tighter than 2 ticks, STOP and raise it with the lead, do not loosen it silently), plus new `tests/deadline_sweeper.rs` (late settle after a fired deadline: slot not re-issued until settle; 8 × 1,000 calls with `call_timeout` = 1 s produce no spurious deadline).
3. **Claim fast path (A4).** The first `try_claim()` runs before `notified()` is created. On `AllBusy` the loop is today's: create, `enable()`, re-check, wait. `RenderClaim::drop`'s `notify_one` is unchanged (a stored permit is harmless). Pinned by `claim_or_wait_wakes_when_claim_released`, `claim_or_wait_times_out_when_all_busy` and the busy tests.
4. **Adaptive offer (A7, R1).** Semantics of a page are unchanged in both states: an all-hit page is ONE call either way, and a miss page is one call while offering and two while not (exactly today's declined path). The state switches only on observed outcomes. Writes to the shared per-route cell happen only on a state change or while the streak is < 64 (no RMW per request in the steady state). Pinned by `tests/plan_offer.rs` (M-like route: offer stays on and `bun_calls` stays 1; I-like route: after 64 all-hit planned calls `LoaderRequest.plan` is absent, `bun_calls` stays 1 and the bytes are identical; first miss → offer back on) and the existing `single_roundtrip` suite.
5. **Template lowering is output-identical (C2–C4).**
   - C2 removes a `set` only when the row body never references the variable. The printer records reads per frame; it does not guess from text.
   - C3 emits `css_decls(k1, v1, …)` with the pairs in the order minijinja's dict literal iterates them: **sorted by key bytes, a duplicate key keeping the last value** (a `BTreeMap`; minijinja 3 without `preserve_order`). Keys rejected by `css_key` are dropped at compile time exactly as `style_obj_to_css` drops them at render. `css_decls` is a plain wrapper over `style_obj_to_css`.
   - C4 is applied only to keys matching `^[A-Za-z_][A-Za-z0-9_]*$` that are not jinja keywords (`true false none and or not in is if else`). An optional member keeps today's guarded form.
   - Pinned by `dual_eval` unchanged, new lowering tests with style objects of 0/1/3 keys including an unsorted and a duplicated key, and the snapshot diff.
