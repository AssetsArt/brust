# M2x — minijinja 3.0 upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

owner: 22499151-e133-4508-b358-d7fa4d2851c3 (Detoro) · authority: in-loop · base: `v2` @56135ad (m2c merged)

**Goal:** Move the workspace from minijinja 2.24 to 3.0 (released 2026-10-08) without changing a single rendered byte for existing fixtures, or, where 3.0's Jinja2-aligned semantics differ from the JavaScript semantics the compiler emits, make the emitter produce JS-faithful output again (the dual-evaluation gate is the arbiter). Approved by the human 2026-10-09 ("แยก lane minijinja 3").

**Architecture:** one dependency bump; mechanical API fixes at the 19 call sites listed in Task 1 (`Value::from_serialize` → `value::Serde`, `serde` feature stays explicit); then a semantic probe: a table of JS expressions whose 3.0 Jinja evaluation is known to have changed (floor division, modulo sign, division by zero, booleans as numbers, unary minus precedence, `round`, `and`/`or` folding) is run through the existing dual printer test against Bun; every divergence is fixed in the emitter (`crates/brust-compiler/src/lower/server_expr` printers) by routing the operator through a `brust-jinja` filter that implements JS semantics, never by accepting the divergence.

**Tech Stack:** minijinja 3.0.0 (`default-features = false`, features `builtins, macros, multi_template, serde`), Rust nightly per `rust-toolchain.toml`.

**Spec:** minijinja `CHANGELOG.md` 3.0.0 "Breaking Changes" and "Template Behavior"; `UPDATING.md` in the minijinja repo; compiler spec §4.4 (server expression printing), §11 (dual evaluation).

## Global Constraints

- Zero golden drift unless explained: after the bump, `cargo test -p brust-compiler --test fixtures` must pass WITHOUT `BRUSTC_UPDATE=1`. A fixture that renders differently is a semantic drift to fix in the emitter, not a golden to regenerate. (Jinja source goldens do not change at all in this lane unless Task 2 adds a filter call.)
- The dual-evaluation harness (`cargo test -p brust-compiler --test dual_eval`) and the dual printer test (`--test dual_printer`) are the arbiters: server paint must equal Bun's evaluation.
- `AutoEscape::None` with explicit `| e` stays; `UndefinedBehavior::Chainable` stays; no new auto-escape or undefined behaviour.
- Do not enable minijinja's `json` feature or its `tojson`; `json_attr` stays ours.
- Do not adopt auto-reload in this lane (`Environment::set_auto_reload(false)` explicitly in `brust-server` so the server keeps its one-parse-at-boot rule; auto-reload is the M3 dev server's business).
- Gates before every commit: `cargo fmt --all`, `cargo clippy --workspace --exclude bun_react_compiler --no-deps -- -D warnings` (brust-napi included once it exists), `cargo test --workspace --exclude bun_react_compiler`; after the last task `bun run battery` twice (no diff), `bun test scripts/battery`, `bun run browser-test`, and the `packages/brust` e2e (`cd packages/brust && bun test`) because the napi addon links `brust-server`.
- Boundary: `Cargo.toml`, `Cargo.lock`, `crates/brust-jinja/**`, `crates/brust-compiler/src/lower/**`, `crates/brust-compiler/src/lower/render_debug.rs`, `crates/brust-compiler/tests/{dual_eval.rs,dual_printer.rs,lower_review.rs,lower_template.rs,harness/**}`, `crates/brust-server/src/{render.rs,pipeline.rs}`, `crates/brust-server/tests/render.rs`, `docs/plans/m1a-followups.md`, `docs/design/2026-10-08-react-compiler-design.md` (§4.4 note if a filter is added).

## Review Focus

1. **`a % b` with a negative dividend** (`-7 % 3`): JS gives `-1`, Jinja2/3.0 gives `2` — Task 2 pins it; the emitter must print a JS-faithful form.
2. **`a / 0`**: JS gives `Infinity` (or `NaN` for `0/0`); 3.0 raises an error → a page would 500. Task 2 decides: the emitter prints `js_div(a, b)` returning a value the paint can show (`Infinity`), pinned by the dual printer.
3. **Boolean arithmetic** (`true + 1`, `count + checked`): JS gives `2`; 3.0 now also treats booleans as numbers (previously an error?) — Task 2 pins both directions so the behaviour is recorded, not assumed.
4. **`-obj.prop`** precedence: 3.0 fixed it to negate the member; the emitter may have parenthesised defensively — Task 2 pins that output is unchanged.
5. **Undefined-value errors with debug info**: `render_err` in `brust-server/src/render.rs` must still produce the template name + line; Task 1 keeps the existing test green.

- [ ] **Step 1: Add probe cases** to `dual_printer.rs` (each is a JS expression over `sample_ctx()`; the test already evaluates the same expression in Bun and compares the painted string):
```
-7 % 3            // JS -1; Jinja2 2
7 % -3            // JS 1;  Jinja2 -2
7 / 2             // 3.5 both
7 // 2 is not JS — skip; but `Math.floor(7/2)` → 3
1 / 0             // JS Infinity
0 / 0             // JS NaN
-1 / 0            // JS -Infinity
true + 1          // JS 2

Math.round(-2.5)  // JS -2
```
