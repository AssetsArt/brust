## Rulings requested
**R1 — How `@brust/core-cf` reaches users.** *Default (lead's):* an `optionalDependencies` entry of `@brust/core`, `workspace:*`, rewritten by `bun publish` like the natives. With this, lane 4's resolution step 4 (from core's dir) works with zero user action. The cost is that every `@brust/core` install, Bun-only apps included, downloads the package (wasm raw ≤ 4 MiB, gzip ~1 MiB [I]), because it carries no `os`/`cpu` filter. A failed fetch never breaks the install. *Alternatives:*
- (a) A plain `dependency`: same bytes, but a fetch failure becomes fatal.
- (b) A separate install: `bun add -d @brust/core-cf@<core version>`, which lane 4's error hint already prints, written by the blank template's devDependencies. That costs Bun-only users nothing, but adds a second version to keep in lockstep inside every app and makes the template diverge from `--brust-dep` handling.

**R2 — One check script for the core-cf package.** *Default:* a new `scripts/core-cf-check.ts <pkgDir> [--pack]`, used by the ci `cf` job, by `dry-run` and by `publish` instead of more inline bash. Its asserts:
1. `package.json` `name === "@brust/core-cf"`, `brust.abi === 1`, and `brust.main`/`glue`/`appModuleDir`/`compatibilityDate`/`workerBuild` present.
2. The file set under `worker/` equals `CORE_CF_WORKER_FILES`, pinned in Task 1 from lane 3's output (expected `index.js`, `index_bg.wasm`, `worker/shim.mjs`), and includes `worker/<brust.main>` and `worker/<brust.glue>`.
3. `index_bg.wasm` raw < `MAX_WASM_BYTES = 4 * 1024 * 1024` (= lane 3 R9). It prints `core-cf wasm raw=<n> gzip=<n>`.
4. No `__brust_e2e` bytes in the wasm or the glue (the `--e2e` marker).
5. With `--pack`: `bun pm pack` into a temp dir, and the tarball listing equals `package/{package.json,README.md}` + `package/worker/<CORE_CF_WORKER_FILES>`, nothing else.

*Alternative:* inline bash steps like :69-77, duplicated in two jobs (the existing pattern, but untested).

**R3 — worker-build version, single source of truth.** *Default:* every job reads `bun -e "console.log(require('./npm/core-cf/package.json').brust.workerBuild)"`. `core-cf-check.ts --versions` also asserts that `crates/brust-wasm/Cargo.toml`'s `worker = "=<v>"` equals `brust.workerBuild`, because workers-rs and worker-build release in lockstep and lane 3's R1 rewrite is tied to 0.8.7. Lane 3's hard-coded cache key `worker-build-0.8.7` becomes `worker-build-${{ runner.os }}-${{ steps.wb.outputs.v }}`. *Alternative:* a literal `0.8.7` in both workflows (three places to bump).

**R4 — The `cf` CI job's shape.** *Default:*
- one job, blocking (no `continue-on-error`), `timeout-minutes: 45`;
- budget: ≤ 20 min warm, ≤ 40 min cold, with the per-step timings measured in Task 6;
- step order as in Goal, with release-shape wasm first, so a release-leg break shows on every PR, not only at tag time;
- caches: `actions/cache@v4` on `~/.cargo/git ~/.cargo/registry target`, key `cargo-cf-${{ runner.os }}-${{ hashFiles('Cargo.lock','rust-toolchain.toml') }}`, restore-keys `cargo-cf-${{ runner.os }}-` then `cargo-${{ runner.os }}-` (warms the napi `build:debug` from the server job's cache); `~/.cargo/bin/worker-build` per R3 (plus worker-build's download dir for wasm-bindgen/esbuild if Task 1 finds one); `~/.bun/install/cache` (wrangler + workerd + the blank template's wrangler) keyed on `hashFiles('bun.lock','tests/cf/tools.ts','packages/create-app/templates/blank/package.json.tmpl')`.
- Making the check required in branch protection is a human setting; the note says so.

*Alternatives:* non-blocking for the preview period (spec header R5 "preview" label); or split into `cf-build` + `cf-e2e` jobs passing an artifact (+1 runner and one more cold setup).

**R5 — Where lane 4's build-target unit tests run.** *Default:* MOVE lane 4's one server-job line (`handlers`, `fetch-in-scope`, `cf-*.test.ts`) into the `cf` job, after `tests/cf`. That gives one place for every Cloudflare test and keeps the 60-min server job from growing. They use lane 4's fake core-cf fixture, so they need no wasm. `handlers.test.ts`/`fetch-in-scope.test.ts` cover the shared Bun path, so they ALSO stay in the server job's unit line. *Alternative:* leave lane 4's line untouched and add nothing.

**R6 — How CI provides the wasm to the scaffold `--target cloudflare` case.** *Default:* build in the `cf` job. Its first step builds the release-shape wasm into `npm/core-cf/worker` and copies `npm/core-cf` to `$RUNNER_TEMP/core-cf`. The last step runs `cd packages/create-app && BRUST_CORE_CF_DIR=$RUNNER_TEMP/core-cf bun test --timeout 600000 test/scaffold.test.ts -t cloudflare`. The server job's full scaffold run skips the case, because no wasm is built there and `npm/core-cf/worker` is gitignored. The case pre-checks `BRUST_CORE_CF_DIR` (else `npm/core-cf`) for `worker/index_bg.wasm`, packs that package, and **unsets** `BRUST_CORE_CF_DIR` for the app's build. *Alternatives:*
- Download the release artifact: impossible on PRs, since release.yml runs on tags/dispatch only.
- Build the wasm in the server job: +5-8 min on the longest job.

**R7 — Artifact naming.** *Default:* `core-cf-worker`, uploaded from `npm/core-cf/worker/`, `if-no-files-found: error`, downloaded by name (not pattern) into `npm/core-cf/worker`. It never matches the natives' `pattern: "bindings-*"` (:62, :103). *Alternative:* `bindings-wasm32-core-cf` (would be swept into `packages/brust/native` by the existing pattern — rejected).

**R8 — Publish order and the native loops.** *Default:*
- `pub` order: runtime-dom → the six natives, iterated from `PLATS` (`bun -e "console.log(require('./scripts/release-files.ts').PLATS.join(' '))"`), never `npm/*` → `pub npm/core-cf @brust/core-cf` → core → create-app.
- The dist-tag list becomes `@brust/runtime-dom @brust/core-cf @brust/core @brust/create-app` + `PLATS`.
- The dry-run loop uses the same explicit order.

*Alternative:* core-cf after core (core briefly references a missing optional dep; harmless but a needless window).

**R9 — Who owns `startPokedexCf` in `tests/server/harness.ts`.** *Default:* lane 5, because its `pokedex.cf.test.ts` must be green at its own merge. This lane touches `harness.ts` only if Task 1 finds lane 5 left the wrangler-spawn harness inline in the test. In that case it lifts it into `startPokedexCf(opts)` beside `startPokedex` (:10-41), with identical assertions. *Alternative:* this lane always lifts the spawn logic shared by `tests/cf` and `pokedex.cf` into one helper (dedupe, wider diff into lane 3's files).

**R10 — The release leg's proof.** *Default:* `build-core-cf` builds and checks (R2) but runs no workerd test: the PR's `cf` job ran the same `build.ts` command plus the e2e (on an `--e2e` sibling wasm). The lead proves the workflow by dispatching `release.yml` on the lane branch (dry-run path, Acceptance A6). *Alternative:* the release leg also scaffolds blank and runs `wrangler deploy --dry-run` on the exact artifact (+3 min per release, needs node + network to npm).

## Risk ledger
- **Bun pack vs the nested `.gitignore` (`npm/core-cf/.gitignore` = `worker/`).** If Bun drops `worker/`, the published package is empty. `core-cf-check --pack` fails in CI, in `dry-run` and in `publish` before `pub` runs.
- **The e2e wasm leaking into a release.** Lane 3's fixture build overwrites `npm/core-cf/worker` with `--e2e`. Only `build-core-cf` produces the artifact, and it never passes `--e2e`. The marker check (R2 #4) blocks it anyway. Task 1 proves the marker is present in e2e builds and absent in release builds.
- **The PATH shim bypassed.** `build.ts` exits 1 without `[pinned]`. If git loses the shims' exec bit, the same error shows: check `git ls-files -s crates/brust-wasm/scripts/pinned-bin` → `100755`.
- **Optional-dep fetch of an unpublished version in tests.** A packed core references `@brust/core-cf@<version>`. `setOverrides` always pins it to a `file:` source. A missed override shows as a `bun install` 404 warning or failure in the scaffold test.
- **Cache pressure.** A second `target/` entry (~2-3 GB with wasm32 + build-std) against GitHub's 10 GB repo limit. Cold-cache runs stay under the 45-min timeout. If eviction makes cold runs common, the note says so and R4's split alternative returns.
- **`napi artifacts` and `npm/core-cf`.** It reads only `npm/<platformArchABI>` (cli 3.10.8 `:12948`). A change in a future cli shows in A6's dry-run.
- **Lane 5 drift [L5].** The test path, gate env and harness location are re-anchored in Task 1. A mismatch is a challenge, not a local edit to lane 5's files.
- **worker-build `--version` format.** The R3 install guard greps `-F` the version. A format change only forces a reinstall, never a wrong version.
