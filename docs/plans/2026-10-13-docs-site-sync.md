## Rules for every docs lane

- **Branch from `docs-site`, not v2.** Create the worktree yourself (Conclave's `lane start` branches from v2): `git -C /Users/detoro/code/brust worktree add .claude/worktrees/<slug> -b lane/<slug> docs-site`, then `conclave task claim <ws> <slug>`. Push `lane/<slug>`; the lead merges it into `docs-site` directly. Worktrees only under `.claude/worktrees/`.
- **Run it.** `bun install` at the repo root, `cd packages/brust && bun run build:debug` (the addon must be fresh: R0.3), then `cd website && bun run dev` (`brust build routes.tsx && brust start`, http://127.0.0.1:1340). Site tests: `cd website && bun test` (harness in `website/test/harness.ts`: `build`, `serve`, `ready`, `until`; tests build into a fresh out dir and drive a real Chromium page). `bun run typecheck` in `website/`.
- **A page is one TSX component** in `website/pages/docs/`, registered in `website/lib/nav.ts` (one entry: slug, title, file, Component, loader). Read `pages/docs/Configuration.tsx` first: the loader returns `toc` + highlighted `blocks` via `codeBlock` from `lib/highlight`; the body uses `CodeBlock`, `Note`, `Step`, `Toc` from `components/docs`. The first comment line of the page states what it covers; **every factual claim carries a `source:` comment (file:line at v2 @00e116c, or `observed:` when you ran it)**. No claim without one.
- **Demos are browser-only** (the site will be a static export on Cloudflare Pages, no Workers): `localStorage`, simulations, lookups; never a real action or server call. Put them in `website/components/demos/`, native tier where possible (useState/useEffect only), with a `data-testid` and a mounted marker like the existing demos.
- **Copy rules from the human:** English only on the site (no Thai), no comparisons with other frameworks, no hostnames or account ids. The production domain is `https://brust.dev`.
- **Tests:** one `website/test/<page>.test.ts` per lane that builds the site, serves it, opens the page, checks the headings and that each demo mounts and does its one thing. Follow `test/caching-page.test.ts`.
- **Screenshots** light, dark and at 400 px width of the finished page, attached as a task note (paths in your scratchpad; never committed).
- **Boundary:** your page file(s), your demo file(s), your test file, and your one `nav.ts` entry. Conflicts in `nav.ts` are the lead's to resolve at merge. Do not touch `routes.tsx`, `Layout.tsx`, `public/app.css` (ask the lead by task note if a style is missing: say the selector you need).
- **Review:** READY → Mellow reviews the page against the v2 docs it cites (standard tier); gates = `bun run typecheck` + `bun test` in `website/` + the screenshots. No ledger row (the website is not in `m1a-followups.md`).
