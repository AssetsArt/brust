# L32 tailwind-compiler: brust compiles Tailwind with the app's own Tailwind version (F135)

owner: 22499151-e133-4508-b358-d7fa4d2851c3 (Detoro) · authority: in-loop · base: main @f3ec0349 (2.0.0-alpha.5) · flow: lane → PR → CI → lead merges · ledger row: F135

## Why

Human order, 2026-10-13: "ทำ F135 ก่อน" (before shadcn/ui). Today `packages/brust/src/build/css.ts` `loadTailwind` imports `bun-plugin-tailwind` from the app. Its last version (0.1.2) embeds the Tailwind compiler 4.1.14 and its own oxide binaries and does not depend on `tailwindcss`, so an app pinned to `tailwindcss` 4.3.x compiles 4.3's `theme.css`/`preflight.css` with a 4.1.14 compiler; utilities added after 4.1 silently do not exist (found by Dew, challenge cd28146c; brust.dev's CSS banner reads `tailwindcss v4.1.14`). shadcn/ui (next) targets current Tailwind v4, so this must be right first.

## Rulings

- **R33.1 Spike first, facts on the task.** Before any code: which packages the official integrations use (`@tailwindcss/vite`, `@tailwindcss/postcss`: `@tailwindcss/node` `compile()` + `@tailwindcss/oxide` `Scanner`), which `tailwindcss` each resolves for the compiler and for `@import "tailwindcss"` (its own exact dependency, or the app's), and therefore which packages an app must install so that the compiler version is the one the app pinned. Post the dependency facts with versions as a task note; the lead rules on the install set if it differs from R33.2.
- **R33.2 brust owns the plugin, the app owns the versions.** Replace `bun-plugin-tailwind` with a brust-owned Bun plugin (in `packages/brust/src/build/`) that does what the official integrations do: `compile()` from `@tailwindcss/node` with `base` = the app root, `Scanner` from `@tailwindcss/oxide` over the compiler's sources (honouring `@source` and `@source not`), `build(candidates)`. Both packages are resolved from the APP (`Bun.resolveSync(…, appRoot)`), never bundled into or depended on by `@brust/core`; brust declares them as optional peer dependencies at most. The default install set (assumed until R33.1 says otherwise): `tailwindcss`, `@tailwindcss/node`, `@tailwindcss/oxide`, all at the same exact version.
- **R33.3 One version or a loud warning.** If the `tailwindcss` the compiler uses differs from the app's installed `tailwindcss`, the build warns with both versions and the exact `bun add -d` command that aligns them. `tailwind-missing` names the new install set.
- **R33.4 Nothing else changes for users.** Same triggers (`@import "tailwindcss"`, `@apply`, `@reference`, `@theme`, `@plugin`), same one-import warning, same output (one hashed minified file per stylesheet), same `brust dev` behaviour (stylesheet edit → CSS swap without reload; `.tsx` edit → rescan + reload), same static target and Cloudflare build.
- **R33.5 Everything that pins the old plugin moves.** `packages/create-app/src/tailwind.ts` `TAILWIND_DEV_DEPS` and the blank template's `package.json.tmpl` (exact pins of the new set, latest stable 4.x at the time of the lane, all equal), `website/package.json`, `docs/css.md` §6 (install command; plus F136's "What it scans" paragraph, folded in here), `docs/create-app.md`, the website's Installation/Css pages if they print the install command. `bun-plugin-tailwind` appears nowhere afterwards except the ledger and old plans.
- **R33.6 Proof.** (a) A test builds a fixture app with `tailwindcss` at version X and asserts the built CSS banner reads `tailwindcss vX`; (b) a test uses a utility that exists only after 4.1 (pick one from the 4.2/4.3 changelog, cite it) and asserts it is in the CSS; (c) existing Tailwind tests (`packages/brust/test/tailwind.test.ts`, create-app `scaffold.test.ts`, website tests) pass; (d) docs-site parity: run `website/scripts/shots.ts` against BASELINE-2 (264 shots; the lead's scratchpad path is on bb `tw:baseline`); the compiler change may move pixels (e.g. the 4.3 `width < X` media syntax, see the half-pixel breakpoints in `docs/plans/2026-10-13-docs-tailwind.md`): every non-zero shot is listed with its cause, and anything over 0.1% needs the lead's written acceptance; (e) brust.dev's built CSS banner reads the new version.
