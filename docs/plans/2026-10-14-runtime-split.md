# L33 runtime-split: a page loads only the client runtime its components use (F139)

owner: 22499151-e133-4508-b358-d7fa4d2851c3 (Detoro) · authority: in-loop · base: main @457b6bfd · flow: lane → PR → CI → lead merges · ledger row: F139 · governed by `docs/plans/2026-10-14-react-parity-north-star.md`

## Why

Human, 2026-10-14: "แบ่ง runtime js ที่ต้อง load ฝั่ง client เป็นกลุ่มๆ เช่นใช้แค่ state ก็มีแค่พวกจัดการ dom กับจัดการ state ตัว js จะได้ไม่ใหญ่แบบ react ในตอนที่ support เยอะแล้ว". As the compiler covers more of React (context, refs, portals, focus management, compiled library components), the client runtime grows; a page that only needs state must not pay for all of it.

Today (`packages/brust/src/build/bundle.ts` `buildRuntime`): one `runtime-<hex>.js` per build, `export * from '@brust/runtime-dom'` + `mount(document.documentElement)`; `packages/runtime-dom/src/index.ts` side-effect-imports every directive (`text html show bind on if model for ref`) and re-exports signals, store, behaviors, islands. On brust.dev it is 17,666 B minified / 6,007 B gzip, loaded whole by every page with a native component.

## Rulings

- **R35.1 Core + features.** The runtime becomes a small core (signals, `mount`/`unmount`, the directive registry, the behavior registry, the chunk loader) plus feature modules: one per directive family (`text`, `bind`, `on`, `show`, `if`, `for`, `model`, `html`, `ref`), `store`, `island` (React island hydration glue), and every future feature the compiler adds (context, portal, focus trap, …) as its own module from day one. A feature registers itself with the core when imported.
- **R35.2 The compiler decides, the page loads exactly that.** The compiler already knows which directives and runtime calls each component's output uses; the manifest records the feature set per component, the build computes it per route (union over the route's components), and the page loads the core plus those feature modules (module script + `modulepreload` for each, all content-hashed, immutable). No feature is loaded "just in case"; a missing feature is a build-time error, never a silent no-op in the browser (test it).
- **R35.3 One instance per page.** Core and each feature are single shared ESM modules (code-split chunks), so two components on one page share one signal graph and one store registry (today's contract); cross-page caching works because the files are per feature, not per route combination.
- **R35.4 Spike decides the mechanics.** Before implementation, measure two options on brust.dev and the pokedex example and post numbers on the task: (a) per-feature ESM modules imported directly by compiled chunks (`import { bindFor } from '/_brust/client/rt-for-<hex>.js'`), (b) one bundle per distinct route feature set. Report request count, total bytes (raw/gzip) per page type, and cache behaviour across navigation. Default: (a); the lead rules if the numbers favour (b).
- **R35.5 Budgets in CI.** The shadcn and react coverage scoreboards gain a column "runtime bytes (gzip)" per row; `ci.yml` fails if the core grows past a recorded budget without the PR updating the budget line with a reason (set the first budget at the measured core size + 10%). The north star's "no bigger than needed" becomes a number.
- **R35.6 Nothing breaks.** Existing apps, the Cloudflare target, the static target, SPA navigation (a newly navigated page may need features the first page did not load: load them before its components mount), dev mode, and islands keep working; the browser test suites (`tests/server/*.chromium.test.ts`, runtime-dom tests) are the proof.

**Amendment 2026-10-14 (ruling on Tiësto's R35.4 spike):** option (a), per-feature ESM modules, confirmed (b cost about 3× the bytes over a 9-page visit and broke the single instance on SPA navigation). R35.1 adjusted: the micro-directives every interactive page uses ship as ONE `basics` module (the spike's five: the ones nearly all native pages need for DOM + state); a feature gets its own module when it is ≥ about 1 KB gzip OR used by a minority of pages: `if`/`for`/`model`/`html` as the spike measured them, `store`, `island`, and every future feature (context, portal, focus trap, …). The rule is recorded in the runtime-dom README so later lanes apply it without asking. The saving on today's brust.dev is about 0 B (its pages use 5–7 of 9 families); this lane is the architecture that keeps S1+ from growing every page, and R35.5's budget is what holds that line.
