# M2a2 — ssr job `props` map and `@brust/brust` import specifiers Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

owner: 22499151-e133-4508-b358-d7fa4d2851c3 (Detoro) · authority: in-loop · base: `v2` @47e5c5c (after m2a-compiler merged)

**Goal:** Close the two contract gaps the m2c plan draft found: (1) the parent's `ssr` job for a react child carries no mapping from the child's prop names to the parent-scope paths, so no server can build the child's props object; (2) the compiler recognises component-level `cache()` only when imported from `'brust'`, while the published package is `@brust/brust`.

**Architecture:** two local compiler changes. `JobDecl` gains `props: Option<BTreeMap<String, Option<String>>>` filled for `Ssr` jobs at the one place the job is built (`analyze/passes/children.rs:335-370`, where the parent's `(prop, Expr)` pairs are already iterated) using the same path extraction the `instances[]` records use; `read_cache_export` accepts the import specifier `'@brust/brust'` in addition to `'brust'`.

**Tech Stack:** Rust nightly per `rust-toolchain.toml`; `cargo test -p brust-compiler`; goldens via `BRUSTC_UPDATE=1 cargo test -p brust-compiler --test fixtures`.

**Spec:** `docs/design/2026-10-09-m2-server-design.md` S6 amendments ("React-tier SSR wire form" + "ssr job `props`"), S3 (package names). Compiler spec §3 line 148 (`cache` import) — amended by Task 2.

## Global Constraints

- New IR field is `#[serde(default, skip_serializing_if = "Option::is_none")]` so only fixtures with react children change their `expected.ir.json`; inspect every golden diff.
- Fail closed: a child prop whose value is not a plain props path (a literal, a call, a computed expression) is recorded as `null` in the map; the build lane turns a `null` into a build error naming component, job and prop. Never guess a path.
- Gates before every commit: `cargo fmt --all`, `cargo clippy -p brust-compiler -p brust-compiler-cli -p brust-jinja --no-deps -- -D warnings`, `cargo test -p brust-compiler`; after the last task also `bun run battery` twice (no diff), `bun test scripts/battery`, `bun run browser-test`.
- Boundary: `crates/brust-compiler/**`, `tests/fixtures/**`, `docs/react-coverage.md`, `docs/plans/m1-exit-report.md`, `docs/design/2026-10-08-react-compiler-design.md` (§3 import line only).

## Review Focus

1. **A react child inside a keyed row** (`per_item` set): the map must carry `[idx]` for row-scoped values (`"move": "pokemon.moves[idx]"`) exactly as `instances[].props` does — Task 1 pins it with the `react-child-row` fixture.
2. **A react child receiving a literal** (`<Reviews limit={3}/>`): `"limit": null` in the map (not `"3"`), tier unchanged — Task 1 pins it.
3. **The same react child used twice** (`_ssr_<id>` and `_ssr_<id>_2`): two ssr jobs, each with its own `props` map — Task 1 pins it.
4. **`cache` imported from somewhere else** (`'./cache'`, `'react'`): still not recognised; `'brust'` and `'@brust/brust'` both are — Task 2 pins all four.
5. **A react PAGE's own ssr job** (`inputs: ["*"]`): `props` stays `None` (the server uses the loader context) — Task 1 pins it on the `react-hook` fixture.
