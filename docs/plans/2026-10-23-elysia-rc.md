# Elysia 2 beta -> rc (elysia@rc): plan

owner: Detoro (22499151) · authority: in-loop · coordinator: Aitthi (eee4366f) · requested by the human 2026-10-23 ("Update elysia beta https://next.elysiajs.com/quick-start/ เป็น elysia@rc")

## Facts (2026-10-23)

- `npm view elysia dist-tags`: `rc: 2.0.0-rc.0`, `next: 2.0.0-beta.32`, `latest: 1.4.30`. `@elysia/eden`: `rc: 2.0.0-rc.0`, whose peer is `elysia >= 2.0.0-rc.0`, so Eden moves with Elysia.
- elysia 2.0.0-rc.0 peers: `typebox >= 1.3.0`, `exact-mirror >= 1.2.6`, `openapi-types >= 12.0.0`, `@types/bun`, `typescript >= 5.7`; deps `deuri ^3`, `memoirist 1.2.3`. Its exports still have `./adapter` and `./adapter/web-standard`, which `packages/brust/src/actions/elysia.ts` imports.
- The Elysia quick start installs `elysia@rc` and says schemas use `typebox`, not `@sinclair/typebox`; Web Standard hosting exports `app.fetch` and never calls `.listen()`.
- Today every live reference pins `elysia 2.0.0-beta.30` and `@elysia/eden 2.0.0-beta.6` exactly (decision R7 in `docs/plans/2026-10-11-m3f-actions-elysia.md`: exact pins, because `mountActions` checks `app instanceof Elysia`, and two copies break that).

## Decisions

- **D1. Peer range:** `packages/brust/package.json` `peerDependencies` become `"elysia": "^2.0.0-rc.0"` and `"@elysia/eden": "^2.0.0-rc.0"` (still optional). Why: the human asked for `elysia@rc`. A user who runs `bun add elysia@rc` must satisfy the peer when rc.1 or 2.0.0 ships, and a range peer resolves to the app's single copy, so the `instanceof` check still sees one Elysia. This replaces R7's exact peer pin. Rejected: an exact `2.0.0-rc.0` peer (every rc bump would need a brust release, and `elysia@rc` would soon mismatch it).
- **D2. Everything we install ourselves pins exactly `2.0.0-rc.0`** (elysia and @elysia/eden): `packages/brust` devDependencies, `packages/create-app/templates/blank/package.json.tmpl`, `examples/pokedex`, `bench/package.json`, `bench/apps/brust`, `tests/fixtures/{cf-cache,cf-l2,cf-min,l2-redis,l2-relay}`, then `bun install` to refresh `bun.lock`. Why: tests and new apps use the pair brust was tested with.
- **D3. Docs install with the tag:** `bun add elysia@rc @elysia/eden@rc` in `docs/actions.md`, `website/pages/docs/Actions.tsx`, `website/pages/docs/Installation.tsx`, `website/pages/docs/cookbook/FormAction.tsx`; state once on the Actions page that brust supports Elysia `^2.0.0-rc.0`. Update the version comment in `packages/brust/src/actions/elysia.ts`.
- **D4. Not touched:** historical records (`docs/plans/*` other than this file, `docs/design/*`, `docs/transcripts/*`, `bench/results/*`, `bench/RESULTS.*`, `bench/lib/fixtures/*`).
- **D5. API drift is fixed in the lane**, never hidden: if rc changed an API brust uses (adapter shape, `compile()`, `WebStandardAdapter`, `problem`, `HTTPError`, `t`, Eden client types), adapt brust's code and say what changed in the READY. If a drift needs a design decision, file a task challenge.
- **D6. Release:** ships in the next alpha; the notes say users must move to `elysia@rc` / `@elysia/eden@rc`.
