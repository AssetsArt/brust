# L31 docs-tailwind: the docs site is styled with Tailwind CSS v4 (F132)

owner: 22499151-e133-4508-b358-d7fa4d2851c3 (Detoro) · authority: in-loop · base: v2 @3f9ceabc · flow: lane → PR → CI → lead merges (one at a time) → lead redeploys · ledger row: F132 · depends on: L29 `docs-global-css` (F130) merged first

## Why

Human request, 2026-10-13: "แก้ css ทั้งหมด ของ docs site เป็น tailwindcss v4 เลยได้ไหม" — the whole docs site's styling moves to Tailwind CSS v4, the same stack the blank template now ships (L28), so the site dogfoods it.

Today: one hand-written stylesheet (`website/public/app.css`, 498 lines / 47 KB; L29 moves it to `website/app.css` and through the brust CSS pipeline), ~540 `className` uses across `website/components/**` and `website/pages/**`. The skin is neo-mirai (`website/design/mockup.html` is the canon): oklch tokens on `:root` with a dark band under `prefers-color-scheme` and `[data-theme]`, Nunito + Azeret Mono, a 112 px paper grid, terminal panes, motion under `prefers-reduced-motion: no-preference`.

## Rulings

- **R32.1 The look does not change.** This is a re-implementation, not a redesign. Every lane proves visual parity with the R32.6 harness against the baseline captured before T1; a pixel difference above the threshold is a finding the lane fixes or the lead accepts in writing.
- **R32.2 Tokens are Tailwind theme variables.** `app.css` = `@import "tailwindcss";` + `@theme inline { --color-paper: var(--paper); … --font-display: …; --font-mono: …; --ease-mirai: …; --animate-*: … }` with the existing `:root` / dark / `[data-theme]` blocks kept as the variable source. Colors switch theme through the variables, so components write `bg-paper text-ink border-rule` with no `dark:` variants (a `dark:` variant only where light and dark differ by more than a color). Every existing token keeps its name as `--color-<name>` (`--color-amber-ink`, `--color-term-fg`, `--color-sy-kw`, `--color-ty-fire`, `--color-pz-sky0`, …). No `tailwind.config`; v4 CSS-first only. Pinned dev deps `tailwindcss 4.3.3` and `bun-plugin-tailwind 0.1.2` (same as the blank template's `TAILWIND_DEV_DEPS`).
- **R32.3 Utilities in markup; CSS only where utilities cannot say it.** When the migration is done, `app.css` holds only: the import, `@theme`, the token blocks, `@keyframes`, `@custom-variant` if needed, a short `@layer base` (body grid/halo background, `::selection`, scrollbar styling for code panes), and a `@layer components` list of exceptions, each with a one-line comment why a utility cannot express it (e.g. generated markup we do not write classes for: the syntax highlighter's spans, the docs body's tables/headings produced from page data; clip-path typing driven by CSS variables). Arbitrary values (`w-[34rem]`) are allowed when they are the design's real numbers; a class string longer than ~12 utilities that repeats in 3+ places becomes a component (a TSX component, not an `@apply` class), except inside `@layer components` exceptions.
- **R32.4 Breakpoints and motion.** The two existing breakpoints become theme breakpoints (`--breakpoint-narrow: 35rem` for the 560 px rules, `--breakpoint-wide: 61.25rem` for 980 px) used with `max-narrow:` / `max-wide:` (the current CSS is desktop-first). Every animation stays behind `motion-safe:` (or the keyframes block stays under the existing media query); reduced-motion behaviour is unchanged and tested.
- **R32.5 Runtime-set CSS variables stay.** Components that set `--rail`, `--ink-x`, `--ink-s` and similar from code keep doing so; utilities read them with `[transform:…var(--ink-x)…]`-style arbitrary properties or the rule stays an exception (R32.3).
- **R32.6 Parity harness first.** T1 adds `website/scripts/shots.ts` (Playwright, already a dev dependency): every nav route + `/` + the 404, light and dark, 400 px and 1280 px, full page, animations disabled (`reducedMotion: 'reduce'` + a style that stops transitions), fonts awaited; writes PNGs to a given dir; a compare mode diffs two dirs (pixelmatch + pngjs as website dev deps, threshold 0.1, report = route/theme/width + differing pixel %). Baseline: run on v2 after L29 merges, before T1's CSS change; kept in the scratchpad, path in the T1 task note, and regenerated by the lead only.
- **R32.7 Tests follow.** Website tests that assert class names change with the markup; tests that assert behaviour (overflow at 400 px, demos, static build) must pass unchanged. `static.test.ts` gains: the built CSS contains a Tailwind utility the site uses, and is one hashed file.
- **R32.8 brust gaps are findings.** Anything brust's Tailwind support gets wrong (scan misses, dev swap, build warnings, the static target) is recorded on `bb gaps:docs-site` and raised to the lead as a challenge; do not work around it silently.

**Amendment 2026-10-13 (ruling on Mellow's tw-foundation F1):** `--animate-*` theme tokens are added by the first lane whose markup uses an animation utility (in practice `tw-landing`; `tw-shell`/`tw-demos` add their own if they get there first), not by `tw-foundation`: an unused token emits nothing, and the token's name and value are best chosen next to the markup that uses it. Every site animation token is prefixed (`--animate-mirai-<name>`) so it can never shadow a Tailwind built-in such as `animate-pulse`. The 14 `@keyframes` stay unlayered in `app.css` until then; `tw-final` checks that each one is referenced by a token or a remaining exception rule.

**Amendment 2026-10-13 (ruling on Dew's challenge 0483731c, supersedes R32.4's breakpoint values and the lead's 561/981 px note):** `--breakpoint-narrow: 35.03125rem` (560.5 px) and `--breakpoint-wide: 61.28125rem` (980.5 px). The 4.1.14 compiler the site builds with (F135) emits `max-width: calc(X - .001px)`, which Chromium rounds back to inclusive, while 4.3 emits `width < X`; a half-pixel breakpoint gives 560/980 in and 561/981 out under both, verified with `matchMedia` and parity at 560/561/980/981 px.
