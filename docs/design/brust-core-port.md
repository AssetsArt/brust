## manifest notes (contract for m2a, accepted by the lead 2026-10-09; spec S6 amendments)
1. `jobs[].per_instance` is the **context path of the list** (`"pokemon.moves"`), not the client loop member (`_l1`).
2. `children[].props` maps each child prop name → a parent-context path, with the literal `[idx]` standing for the current row of the `per-row` list (`"move": "pokemon.moves[idx]"`). It must cover the root segment of every `inputs` entry of the child's jobs; boot fails with `ManifestError::UncoveredInput` otherwise.
3. `jobs[].inputs` are relative to the component's props (`"item.price"`, as the M1 IR emits); a leading `props.` segment (spec §3 example) is accepted and stripped.
4. `k` in `__<childId>_<k>` is the 1-based ordinal of that child id within `children` (template order).
5. **`jobs[].outputs`** (ruling cb881050; serde default `[]`): copied from the IR. Result k lands at `outputs[k]` in the owning component's overlay. What "result k" means, from real compiler output (`tests/fixtures/react/`, and `brustc --emit server` of `PriceRow.tsx`: `return { _s1: fmt(item.price, unit) }`): **precompute** returns ONE object keyed by slot name, so `outputs[k]` gets `value[outputs[k]]` (keyed, not positional; a missing key or a non-object is a 500, nothing cached); **ssr** returns one HTML string, which goes to `outputs[0]` (an ssr record with more than one output fails boot). A **`per_instance`** job runs once per row of its list and `outputs[0]` is an array indexed by row (template: `{{ _ssr_<id>[_i1] | safe }}`, `rowReact_631ddf5f.jinja`); such a job must have exactly one output (boot). Output names must be identifiers (boot). Empty `outputs` (older manifests): precompute objects are spread, a chain ssr result lands at `_ssr_<componentId>`.
6. **`jobs[].target`** (`ssr`): the react component the worker renders; must name a known component (boot); copied to `JobCall.target` (camelCase, omitted when absent). A react child is not a `children[]` record: its ssr job sits in the parent's `jobs[]` (fixture `teamPage_g7/j0`, target `teamBuilder_h8`); `inject_assets` adds the target's `client` chunk.
7. **`"*"` in `inputs`**: every prop of the component — for a chain entry the loader context without `__children`/`__own` (the same object as `_props`), for a child instance its `child_props`. It is not a path: `BadPath`/`UncoveredInput` skip it, and the job key hashes the whole object.
8. **`jobs[].props`** (v2 extension, NOT in the ruling — see decisions): optional `{ targetProp: parent path }` with `[idx]` = the row of `per_instance` (boot: `[idx]` needs `per_instance`). When present it replaces the parent-scope projection as the `inputs` sent and hashed.

`children[].instances` (ruling 24e8bf17): the wire form is the STRING only — `"static"` or `"per-row:<list path>"`. The withdrawn object form `{k, per_instance}` is rejected at boot (`manifest.rs` `Instances` deserializer). `k` is never on the wire; the server derives it as in note 4.

## v2 decisions beyond the plan
- **Generation-stamped tag index** (`cache/l1.rs`, `cache/job_cache.rs`): each insert stamps a fresh generation; moka's eviction listener prunes a tag-index slot only if its generation matches the evicted value, so replacing a key no longer un-indexes the newer entry (0.1.x pruned unconditionally).
- **Insert/invalidate gate** (`cache/l1.rs`, `cache/job_cache.rs`): "index tags, then moka insert" runs under a shared `RwLock` read guard; tag/user-key invalidation and `clear` take it exclusively. An invalidation can no longer land between the index write and the insert (it used to take the index, remove nothing, and leave the entry live and un-indexed forever). The eviction listener never takes the gate. Unit-tested with a deterministic mid-insert pause (`invalidate_between_index_and_insert_is_not_lost`).
- **Cancel-safe `call_worker`** (`dispatch.rs`): once claimed, the call, bounds check and parse run in a spawned task that owns the `RenderClaim`; a dropped request future cannot free a SAB slot JS may still be writing.
- **L1 `EvalCtx` last-wins + BYPASS rules** (`pipeline.rs` `l1_decision`): header/cookie lists collapse to the last value per name; `query(...)` sees the DECODED names and values (the loader's `req.search`: `?pre%76iew=1` is `preview`, `mode=dr%61ft` is `draft`) while the CacheKey keeps the raw sorted query; a case-insensitive name collision in any of them, or a query name repeated after decoding, bypasses L1 (read and write), so the key never diverges from what the loader reads.
- **Reserved loader keys dropped** (`pipeline.rs` `merge_loader_data`): server-owned names — `__outlet`, `__children`, `__own`, `_props`, keys starting `_ssr_`, and keys matching exactly `_s<digits>` / `_id<digits>` — are dropped with a `warn`; every other key (`_id`, `_session`, `_s`, a GraphQL `__typename`) overrides the context. Overlays already beat the base ctx; this is defence in depth. Child slots `__<id>_<k>` need no reservation: they live under `__children`.
- **`cache.key` formatting** (`pipeline.rs` `plan_key`): `cache.key` is a props path; its value (string raw, any other non-null value canonical JSON) is the user key, and the JobKey is `"k:<componentId>/<jobId>/<user key>"`; null/unset falls back to the hashed inputs key.
- **`BadPath` boot validation** (`manifest.rs` `check_paths`): every job `inputs`, `cache.key`, `per_instance`, child `instances` list path and child `props` path is parsed at load; a malformed one (or `[idx]` outside a per-row child's props) fails boot with `ManifestError::BadPath` instead of 500-ing every request.
- **`/_brust/` limited** (`pipeline.rs` `safe_rel`): `/_brust/<rel>` serves only `client/<file>` where `<file>` passes `is_safe_island_filename` (.js) or `is_safe_css_filename` (.css); `manifest.json`, `jobs.js` and `jinja/` in `dist/` are never served. `/public/<rel>` serves `dist/public` with per-segment checks.
- **React SSR wire form (ruling cb881050)** (`pipeline.rs` `collect_jobs`/`merge_result`/`check_value`): parent-hosted ssr jobs write their HTML to `outputs[0]` in the parent's `__own` overlay (per-row: an array by row); the legacy "static child ssr in the parent's scope" path survives only for records without `outputs`. `JobCall` gains `target` and, for `per_instance` jobs, `row` (0-based). Keys: a `per_instance` row is keyed `<jobId>#<row>` unless the record has a `props` map (then the row's props are the content key, so equal rows are one computation).
- **`jobs[].props` (v2 extension, pending a ruling)**: the IR's parent-hosted ssr job carries parent-scope `inputs` only (`twice-react`: `inputs: ["a"]` for `<Reviews productId={a}/>`; `row-react`: `inputs: ["items"]`, `per_item: "it"` for `productId={it.id}`), so `jobs[target].ssr(inputs)` would receive `{a}` / `{items}` instead of `{productId}`. Without `props` the server sends exactly what the ruling says (parent-scope projection, plus `row`); with `props` it sends the target's props. The build lane can derive `props` from the IR template's `Component.props` (the same mapping the parent template prints as `x-props`).
- **Child-instance `_props` not seeded**: no compiler template reads it. A react child's host is printed by the PARENT template with an inline dict (`x-props='{{ {"productId": a} | json_attr }}'`, `twiceReact_42d42134.jinja`); only a component's OWN record template (react page / client-only page) prints `_props`, and that is a chain entry.
- **Child slots scoped per parent** (`pipeline.rs` `seed_child_slots`/`merge_result`, `finish`): `k` is per parent template, so child-instance slots live at `ctx["__children"][<parentId>]["__<childId>_<k>"]` (plus that parent's `_ssr_<childId>`); `render_chain`'s overlay closure adds the rendering component's map alongside its `_idN` and `__outlet` (overlay wins over the base ctx). A layout and a page that inline the same child no longer collide. `__children` is a `__` key, so loader data can't spoof it; the L1 entry stores the whole ctx, so a HIT renders identically.
- **useId instance format (F39)** (`render.rs` `use_ids`): `brust-<routeId>-<instance>-<n>`; instance = the component id for chain entries, `<parentId>.<childId>_<k>` for a static child instance, `<parentId>.<childId>_<k>-<row>` for a per-row instance. Ids are opaque strings: stability and uniqueness per route are the contract. Context keys are 0-based (`_id0` = first `useId()`; lead ruling on challenge a76cefb2, spec d687ca5); the id value suffix stays 1-based.
- **Unique `JobCall` ids** (`pipeline.rs` `plan_one`): chain job `"<componentId>/<jobId>"`; child job `"<parentId>/<childId>_<k>/<jobId>[/<row>]"`. The plan's call id carries the parent and the ordinal, so a child inlined twice (k=1, k=2) or by two parents gets distinct ids instead of collapsing in the result map (was a cold-cache 500). Log fields come from the plan the result id names; ids are never parsed.
- **Loader headers replayed on L1 HIT** (`cache/l1.rs` `CachedEntry.headers`): the loader's response headers are stored with the ctx (`Arc<[(String, String)]>`) and replayed on a HIT, so MISS and HIT carry the same headers (a `Set-Cookie` response is never cached).
- **Job result without `value` is a 500** (`pipeline.rs` jobs step): a `JobResult` with neither `value` nor `error` fails the request like a job error (logged with component/job id), nothing cached.
- **`cache({key})` job keys are namespaced** (`pipeline.rs` `plan_key`, `cache/job_cache.rs` `key_index`): `k:<componentId>/<jobId>/<value>`, so two components keyed on one value no longer share (and serve each other's) entry. `Server::invalidate({key})` still takes the user key alone: the job cache keeps a user key → JobKeys index (generation-guarded and pruned like the tag index) and removes every entry under it. String `"5"` and number `5` share a user key.
- **Chain job results are per component** (`pipeline.rs` `merge_result`, `finish`): every component numbers its precompute slots from `_s1`, so a chain component's precompute keys and its `_ssr_<id>` live at `ctx["__own"][<componentId>]`, overlaid only while rendering that component (like `__children`; overlay beats base). A layout's `_s1` and its page's `_s1` no longer collide, and the L1 entry (whole ctx) renders identically on a HIT.
- **`_props` seeded** (`pipeline.rs` `finish`, `all_props`): every chain component's overlay carries `_props` = the merged loader context (params, path, loader data — without `__children`/`__own`), which island hosts print as `x-props='{{ _props | json_attr }}'`; `"*"` inputs are the same object.
- **Miss de-dup** (`pipeline.rs` jobs step): plans sharing a JobKey that miss in one request are sent to the worker once (the first plan's call id) and the value is fanned out to every plan; the job cache is written once.
- **Verdict sanity** (`pipeline.rs` loader step): a redirect status outside 300-308 becomes 302 (warn); non-ASCII characters in `location` are percent-encoded as UTF-8 (`/café` → `/caf%C3%A9`); a `location` holding any control character (CR, LF, NUL, TAB, DEL, C1) is a 500 + error log instead of a Location-less redirect; an `httpError` status outside 400-599 is a 500 + error log.
- **Hashed-name immutable rule** (`pipeline.rs` `is_hashed`): the `-<hex>` stem suffix must be ≥ 6 lowercase hex chars AND contain a digit, so `brand-facade.css` stays `max-age=3600`.
- **HTTP hygiene** (`pipeline.rs`, `server/body.rs`, `server/mod.rs`): HEAD page responses carry the GET's `Content-Length`; 405 carries `Allow: GET, HEAD`; static responses carry `X-Content-Type-Options: nosniff`; a static file is served only if its canonical path (all symlinks resolved) lies under the canonical `dist/public` or `dist/client`; HTTP/1 header-read timeout `Tuning.header_read_timeout_ms` (default 10 s, hyper `TokioTimer`).
- **Known limits (documented, not fixed)**: `invalidate({key})` evicts job entries only — L1 pages already rendered from that job value stay until their ttl/tag/path invalidation; the job cache is bounded by entry count (`job_cache_capacity`), not bytes; a request may wait up to 2× `claim_timeout_ms` for workers (once for the loader call, once for the jobs call).
