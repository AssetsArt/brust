# Routing + Radix Tree + errorBoundary Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the hard-coded `path → render` dispatch with a declarative `routes.tsx` table plus a Rust-side radix tree for URL matching. Add per-route `errorBoundary` so render and loader exceptions are caught locally instead of returning a plain `text/plain` 500. The render-call IPC contract evolves from `Function<String, Promise<u32>>` (where `String` is the raw path) to `Function<String, Promise<u32>>` (where `String` is now a JSON envelope `{ routeId, path, params }`) — same napi type signature, richer payload.

**Architecture:** Three coordinated changes. (1) A new TS `runtime/routes.ts` defines `defineRoutes` plus the `Route` interface; the user's `routes.tsx` exports `routes = defineRoutes([...])`. (2) The Bun main thread loads `routes.tsx`, extracts each route's pattern, and ships the patterns array into Rust via a new napi export `register_routes(patterns: Vec<String>) -> u32` (returns the count for sanity). Rust builds a `matchit::Router<u32>` keyed by array index = route id. (3) `handle_conn` calls `router.at(path)`, builds a JSON envelope, and dispatches into the existing worker pool. Workers parse the envelope, dispatch by `routeId` to the matching component, and render with `params` as a prop. `errorBoundary` is a per-route optional `(props: { error: Error }) => ReactNode`; the worker `try/catch`es the render path, swaps to it on failure, and resolves the same `Promise<u32>`. HTTP status stays 200 even in the errorBoundary branch — fixing that needs the richer tsfn return type that the Middleware plan introduces (Tier 2). Children (nested routes) and `loader:` are explicitly deferred — see Out of scope.

**Tech Stack:** Rust 2024 edition, `matchit = "0.8"` (radix tree, used by axum), `serde = "1"` + `serde_json = "1"` (envelope serialization), `napi-rs 3.x`. TS layer keeps React 18 + Bun 1.3.

**Spec source:** `architecture.md` §Routing (lines 297-344): declarative `routes.tsx`, radix tree in Rust, tsfn signature evolves, `errorBoundary` catches thrown loader errors and render exceptions, default to built-in page if not declared. This plan ships the *minimum* of that section that unblocks Tier 2 plans (Cache, Middleware, Server fns).

## Pre-flight: what this plan does NOT do

These are real architecture-doc features that we **defer** to keep the surface area honest:

- **`loader: async (req, params) => {...}`.** Loaders run inside the worker and supply `props` to the component. The pattern is straightforward but introduces a JSON-serializable contract for `req` (cookies, headers, query) that interacts with the Middleware plan's response-header story. Cleaner to land it after Middleware. For now, components receive `{ params, path }` only.
- **`children:` (nested routes).** Single-level routes are enough for Cache + Server fns work. Nesting changes both the radix-tree population (multiple inserts per leaf) and the worker dispatch (layout chain rendering). Lands in its own follow-up.
- **`cache:` per-route field.** Lands with the Cache plan. We *do* shape the `Route` type to leave room for it (an unknown field is permitted but ignored), so the Cache plan only adds reading code.
- **Per-route `middleware:` array.** Same deferral — picked up by the Middleware plan.
- **Custom global `_404.tsx` / `_500.tsx`.** Built-in 404 / 500 only this round. A user-supplied 404 needs a "fallback route" sentinel in the radix tree, which is in scope for a small follow-up after Middleware.
- **Client-side navigation (`/_brust/page/*`).** This is the Navigation plan.

What this plan *does* deliver and downstream plans need:

- A Rust function-shaped `matchit::Router<u32>` populated at startup.
- A stable JSON envelope on the worker IPC boundary.
- A per-route `errorBoundary` hook (component, not lazy-import) so render-time exceptions are recoverable inside one request without crashing the worker.

Create `src/routes.rs` with:

```rust
use std::collections::HashMap;

use parking_lot::RwLock;
use serde::Serialize;

/// JSON envelope shipped across the tsfn boundary for each render call.
/// Worker JS deserializes this and uses `route_id` to pick the component.
#[derive(Serialize)]
pub struct RouteEnvelope<'a> {
    pub route_id: u32,
    pub path: &'a str,
    pub params: HashMap<&'a str, &'a str>,
}

/// Outcome of a match against the radix tree.
pub enum MatchResult {
    Matched {
        route_id: u32,
        envelope_json: String,
    },
    NoMatch,
}

#[derive(Default)]
pub struct RouteTable {
    inner: RwLock<matchit::Router<u32>>,
}

impl RouteTable {
    pub fn new() -> Self {
        Self::default()
    }

    /// Replace the route set. Patterns are inserted in array order; the array
    /// index becomes the `route_id` value matched against by the worker
    /// dispatcher. Called once during boot — `register_routes` rejects a
    /// second call.
    pub fn install(&self, patterns: &[String]) -> Result<u32, RouteInstallError> {
        let mut router = matchit::Router::new();
        for (idx, pattern) in patterns.iter().enumerate() {
            router
                .insert(pattern.clone(), idx as u32)
                .map_err(|e| RouteInstallError::Insert {
                    pattern: pattern.clone(),
                    reason: e.to_string(),
                })?;
        }
        *self.inner.write() = router;
        Ok(patterns.len() as u32)
    }

    /// Match a request path. Returns a fully serialized JSON envelope ready to
    /// hand to the tsfn, or `NoMatch`.
    pub fn match_path(&self, path: &str) -> MatchResult {
        let router = self.inner.read();
        match router.at(path) {
            Ok(matched) => {
                let mut params: HashMap<&str, &str> = HashMap::new();
                for (k, v) in matched.params.iter() {
                    params.insert(k, v);
                }
                let envelope = RouteEnvelope {
                    route_id: *matched.value,
                    path,
                    params,
                };
                // serde_json::to_string on a Serialize struct cannot fail in
                // practice (no IO, all values are valid UTF-8 &str). Unwrap is
                // safe — if it ever fails, that's a serde bug, not user error.
                let envelope_json = serde_json::to_string(&envelope).unwrap();
                MatchResult::Matched {
                    route_id: *matched.value,
                    envelope_json,
                }
            }
            Err(_) => MatchResult::NoMatch,
        }
    }
}

#[derive(Debug, thiserror::Error)]
pub enum RouteInstallError {
    #[error("invalid route pattern {pattern:?}: {reason}")]
    Insert { pattern: String, reason: String },
}
```

```typescript
import { createElement, type ComponentType, type ReactNode } from 'react'
import { renderToString } from 'react-dom/server'

export interface RouteContext<Params = Record<string, string>> {
  params: Params
  path: string
}

export interface ErrorBoundaryProps {
  error: Error
}

export interface Route<Params = Record<string, string>> {
  path: string
  Component: ComponentType<RouteContext<Params>>
  /** Optional component invoked when Component (or, later, loader) throws. */
  errorBoundary?: ComponentType<ErrorBoundaryProps>
}

/** Identity helper that pins the `routes` array's element type for the IDE
 * and ensures route_ids are stable across worker reloads (they = array index).
 */
export function defineRoutes(routes: Route[]): Route[] {
  return routes
}

/** Wire-level shape of the JSON envelope produced by Rust `routes::match_path`.
 * Keep this struct in sync with src/routes.rs::RouteEnvelope.
 */
export interface RouteCall {
  route_id: number
  path: string
  params: Record<string, string>
}

/**
 * Build a render callback for a given routes table. The returned function is
 * what gets passed to `brust.registerRenderer(view, fn)` on the worker side.
 */
export function makeRenderer(
  routes: Route[],
  view: Uint8Array,
): (envelopeJson: string) => Promise<number> {
  const encoder = new TextEncoder()
  // Pre-build the byId map once; lookup is O(1) per request.
  const byId = new Map<number, Route>()
  routes.forEach((r, i) => byId.set(i, r))

  return async (envelopeJson: string): Promise<number> => {
    const call = JSON.parse(envelopeJson) as RouteCall
    const route = byId.get(call.route_id)
    if (!route) {
      // Rust matched against the router but this worker doesn't know route_id.
      // Only possible if the worker's `routes.tsx` drifted from main's. Report
      // by writing a marker into the SAB and resolving 0 (Rust treats as error).
      return 0
    }
    let html: string
    try {
      html = renderToString(
        createElement(route.Component, { params: call.params, path: call.path }),
      )
    } catch (renderErr) {
      // Render exception: swap to errorBoundary if declared; otherwise rethrow
      // so the tsfn Promise rejects and Rust emits its existing 500 path.
      if (!route.errorBoundary) throw renderErr
      const boundary: ReactNode = createElement(route.errorBoundary, {
        error: renderErr instanceof Error ? renderErr : new Error(String(renderErr)),
      })
      html = renderToString(boundary as any)
    }
    const { written } = encoder.encodeInto(html, view)
    return written ?? 0
  }
}
```

## Risks and caveats

1. **`matchit` static-vs-dynamic conflict.** matchit returns an error if `/blog/:slug` and `/blog/about` are registered together because of pattern ambiguity. The example uses only `/blog/:slug`, so we don't hit it; but the moment a user declares both, `register_routes` returns an error and the app fails to boot. Document in the architecture entry; the user fix is to reorder or restructure routes.
2. **`route_id` stability.** Workers spawn after `registerRoutes` and load the same `routes.tsx` file by path — they reach the same `byId` ordering. If a future change loads routes from a database or some non-deterministic source, the array index is fragile. Pin it to an explicit `id` field on `Route` then. Not needed today.
3. **`renderToString` and React error containment.** React 18's `renderToString` does throw on a component exception; the worker's `try/catch` catches it as long as the error propagates synchronously. If a component returns a Promise (server components, suspense), `renderToString` returns whatever shell it has at suspend time — that is a `renderToPipeableStream` story, deferred to the HTML Streaming plan.
4. **`workerId` post-processing kludge.** Documented inline in `example/hello-world/index.ts`. It is an example concern, not a framework concern; users not relying on `worker_id` in their HTML never see it. Cleaner solution lands with the loader/context plan.
5. **Status code for `errorBoundary`.** 200 — see plan intro. Middleware plan upgrades this.
6. **No `/_brust/*` reserved prefix yet.** A future user who declares `path: '/_brust/foo'` will collide with the Agentic surface (`/_brust/agentic/...`) and Server fns (`/_brust/action/...`). The current `register_routes` will accept that pattern; the conflict only manifests when the conflicting subsystem lands. Worth a one-line warning in the architecture doc; the Server-fn plan will own the actual reservation.
