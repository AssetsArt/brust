# LRU Cache Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Rust-side LRU cache that short-circuits the worker pool when a route declares `cache: { ttl_seconds, vary? }`. Cache hits respond entirely from Rust (no napi tsfn call) — preserving Brust's "Rust everywhere except React" model. Routes without a `cache` declaration bypass the cache (opt-in).

**Architecture:** New `src/cache.rs` exposes `LruCache<CacheKey, CachedEntry>` behind `parking_lot::Mutex` (bounded LRU eviction by entry count; TTL expiry checked on read). Per-route cache config travels with the route table: the existing `register_routes(patterns: Vec<String>)` signature changes to `register_routes(configs: Vec<String>)` where each `configs[i]` is a JSON-encoded `RouteConfig { path, cache?: { ttl_seconds, vary?: string[] } }`. `RouteTable` holds per-route_id config in a parallel `Vec<Option<CacheConfig>>`. `handle_conn` after `match_path` does: (1) if no cache config or `vary` includes headers we don't have → skip cache → worker; (2) else build `CacheKey(method, path, sorted_query, selected_vary_values)` → `lru.get(key)` → if hit and not expired, write cached body, continue; (3) else call worker, store result, write. Memory budget: hard-coded 1000 entries. Control-socket invalidation deferred to the CLI plan.

**Tech Stack:** Rust 2024 edition, `lru = "0.12"` (popular bounded LRU), `serde` for the JSON config (already a dep). TS side: extend `Route` interface; JSON-encode in `brust.registerRoutes(...)` call.

**Spec source:** `architecture.md` SCache:
> LRU keyed on `method + path + sorted query + vary_headers`. Per-route opt-out (`cache: false`) for authed/personalised pages. Programmatic invalidation via control socket (`brust-cli invalidate /path`). TTL-based eviction.

The SCache prose says "per-route opt-out" implying default-on. This plan flips that to **default-off** (opt-in via explicit `cache:` field) because:
1. The example app's existing tests (and any user's authed app) MUST not silently cache without explicit declaration — privacy/correctness > performance.
2. matches what the Plan E commit message left for follow-up: "`cache: { vary, ttl_seconds }` — Cache plan."
3. architecture.md text updated accordingly.

## Context: cache-key composition + per-route plumbing

**CacheKey fields:**

| Field | Source | Notes |
|---|---|---|
| method | `httparse` parsed request | currently always GET (server only accepts GET) — included for forward compat |
| path | raw path from request line | NOT the matchit pattern; the actual URL path so `/blog/foo` and `/blog/bar` are distinct |
| sorted_query | query-string part after `?`, sorted | `?b=2&a=1` and `?a=1&b=2` produce the same key |
| vary_values | `vary` config × request headers | each declared vary header's value joined; missing header = empty string |

**RouteConfig wire shape (JSON over the napi boundary):**

```json
{
  "path": "/blog/{slug}",
  "cache": {
    "ttl_seconds": 60,
    "vary": ["accept-language"]
  }
}
```

`cache` is optional. Missing or `null` → no caching for that route.

**TS `Route` interface gains an optional `cache` field:**

```typescript
export interface Route<Params = Record<string, string>> {
  path: string
  Component: ComponentType<RouteContext<Params>>
  errorBoundary?: ComponentType<ErrorBoundaryProps>
  /** Opt-in cache. Omit for no caching (default for authed/personalised routes). */
  cache?: {
    /** Time-to-live in seconds. After this, cache miss + re-render. */
    ttl_seconds: number
    /** Request headers that affect content. Each becomes part of the cache key. */
    vary?: string[]
  }
}
```

```rust
use std::num::NonZeroUsize;
use std::sync::atomic::{AtomicU64, Ordering};
use std::time::{Duration, Instant};

use parking_lot::Mutex;
use serde::Deserialize;

const CACHE_CAPACITY: usize = 1000;

/// Per-route cache config. Lands in RouteTable alongside the matchit router.
#[derive(Debug, Clone, Deserialize)]
pub struct CacheConfig {
    pub ttl_seconds: u64,
    #[serde(default)]
    pub vary: Vec<String>,
}

/// Cache key. Hash + Eq derived; ordering of `sorted_query` and `vary_values`
/// is the caller's responsibility (callers must sort before constructing).
#[derive(Debug, Clone, PartialEq, Eq, Hash)]
pub struct CacheKey {
    pub method: String,
    pub path: String,
    pub sorted_query: String,
    /// For each declared vary header in declaration order: the request value
    /// (empty string if header was missing).
    pub vary_values: Vec<String>,
}

/// Entry held in the LRU. Stores the full HTTP response bytes ready to write
/// — including the HTTP/1.1 status line and headers from build_response — so
/// hits are a single write_all syscall away from the wire.
#[derive(Clone)]
pub struct CachedEntry {
    pub response_bytes: Vec<u8>,
    pub inserted_at: Instant,
    pub ttl: Duration,
}

impl CachedEntry {
    pub fn is_expired(&self) -> bool {
        self.inserted_at.elapsed() >= self.ttl
    }
}

pub struct LruCache {
    inner: Mutex<lru::LruCache<CacheKey, CachedEntry>>,
    hits: AtomicU64,
    misses: AtomicU64,
}

impl LruCache {
    pub fn new() -> Self {
        Self {
            inner: Mutex::new(lru::LruCache::new(
                NonZeroUsize::new(CACHE_CAPACITY).expect("CACHE_CAPACITY > 0"),
            )),
            hits: AtomicU64::new(0),
            misses: AtomicU64::new(0),
        }
    }

    /// Returns Some(bytes) if a non-expired entry exists. Expired entries
    /// are removed lazily on lookup.
    pub fn get(&self, key: &CacheKey) -> Option<Vec<u8>> {
        let mut guard = self.inner.lock();
        let entry = guard.get(key)?;
        if entry.is_expired() {
            guard.pop(key);
            self.misses.fetch_add(1, Ordering::Relaxed);
            return None;
        }
        let bytes = entry.response_bytes.clone();
        self.hits.fetch_add(1, Ordering::Relaxed);
        Some(bytes)
    }

    pub fn insert(&self, key: CacheKey, response_bytes: Vec<u8>, ttl: Duration) {
        let entry = CachedEntry {
            response_bytes,
            inserted_at: Instant::now(),
            ttl,
        };
        self.inner.lock().put(key, entry);
    }
}

impl Default for LruCache {
    fn default() -> Self {
        Self::new()
    }
}
```

- [ ] **Step 4:** Add the `build_cache_key` helper at the bottom of `src/server.rs`, after `read_full_request`:

```rust
fn build_cache_key(method: &str, full_path: &str, cfg: &CacheConfig, request_buf: &[u8]) -> CacheKey {
    let (path_only, query) = match full_path.split_once('?') {
        Some((p, q)) => (p, q),
        None => (full_path, ""),
    };
    let sorted_query = sort_query(query);
    let vary_values = lookup_vary_headers(request_buf, &cfg.vary);
    CacheKey {
        method: method.to_string(),
        path: path_only.to_string(),
        sorted_query,
        vary_values,
    }
}

fn sort_query(query: &str) -> String {
    if query.is_empty() {
        return String::new();
    }
    let mut pairs: Vec<&str> = query.split('&').filter(|p| !p.is_empty()).collect();
    pairs.sort_unstable();
    pairs.join("&")
}

fn lookup_vary_headers(request_buf: &[u8], vary: &[String]) -> Vec<String> {
    if vary.is_empty() {
        return Vec::new();
    }
    // Parse just enough to walk headers. httparse on the raw buf gives us
    // [Header { name, value }] without allocation. We do an ascii_eq_ignore_case
    // for each declared vary name.
    let mut headers = [httparse::EMPTY_HEADER; 32];
    let mut req = httparse::Request::new(&mut headers);
    let _ = req.parse(request_buf); // safe to ignore — caller already parsed this buf
    vary.iter()
        .map(|name| {
            req.headers
                .iter()
                .find(|h| h.name.eq_ignore_ascii_case(name))
                .and_then(|h| std::str::from_utf8(h.value).ok())
                .unwrap_or("")
                .to_string()
        })
        .collect()
}
```

## Risks / caveats

1. **`lru` crate version 0.12 API.** `LruCache::new` takes `NonZeroUsize`; `get`/`put`/`pop` are the basic ops we use. The crate is stable; version 0.13+ shouldn't break anything important here.
2. **Cache hit path stores full HTTP bytes including `Connection: keep-alive`.** If a future change makes the `Connection` header dynamic (per-request), the cached value will be stale. Today `build_response` hard-codes `keep-alive` so this is a non-issue.
3. **Module-scope counter in `CacheTest.tsx` is shared across requests *within one Worker isolate*.** The test pins `BRUST_WORKERS=1` to make this deterministic. Don't loosen that without also rewriting the test.
4. **Memory budget.** 1000 entries × average response size ~5-50 KB ≈ 5-50 MB. Acceptable for a 16 GB host. If a future user pins a route with `vary: many headers` and huge content, capacity could balloon — `brust.toml [cache] max_entries` lands later to expose the knob.
5. **No cache stats endpoint.** The `hits`/`misses` AtomicU64s in LruCache are populated but not surfaced. A future `/cache-test/_stats` endpoint or napi `getCacheStats()` would help — out of scope here.

## Out of scope

- Control-socket cache invalidation (`brust-cli invalidate /path`). Needs the brust CLI; defer.
- `brust.toml [cache]` section — defer with the CLI/build plans.
- Conditional caching based on response status (only 200 caches today — non-200s aren't reached because cache writes happen on the render-success branch).
- Cache warming / preloading.
- Negative caching (cache 404 / 5xx responses).
- Per-route `cache: false` explicit (omission already opts out).
