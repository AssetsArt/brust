# Release brustjs 0.1.67-alpha

owner: 0ddb11d0-954b-4710-90ce-8191a46fe3c3 · authority: in-loop

## Release target

Ship the AI production opt-in fix currently ending at local-main SHA `d7fa6b1`
as `0.1.67-alpha`. The previous shipped tag is `v0.1.66-alpha`.

## Mandatory order

1. From a release lane containing the complete `origin/main..d7fa6b1` series,
   mirror `.github/workflows/ci.yml` locally.
2. Push the lane branch and open a PR targeting `main`.
3. Wait until every PR check is green. A red or pending check forbids merge.
4. Lead Aoki merges the PR to `main`, switches the integration checkout to the
   resulting remote `main`, and verifies the merged SHA.
5. On `main` only, run `bun scripts/release-bump.ts 0.1.67-alpha`, verify the
   script reports all 15 refs, and commit `chore(release): 0.1.67-alpha`.
6. Create annotated tag `v0.1.67-alpha` on that release commit, push `main`,
   then push the tag.
7. Watch the tag-triggered `release.yml` run to success. Verify the workflow's
   publish job, not only the build matrix.

Never tag or bump on the release lane. `release.yml` does not gate on CI, so the
tag is forbidden until the PR is merged with all checks green.

## Phase A — implementer scope

No source edits. Run and record all exact preflight commands:

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo build --workspace --locked && cargo test --workspace --locked
bun run ci
cd runtime && bun run build:debug && cd ..
bun test runtime/
for f in native-island native-island-ssr cli-new integration; do bun test tests/$f.test.ts; done
```

After local green, push the lane branch, open a PR to `main` summarizing both
the missing build artifact and native dev-client leakage, and run
`gh pr checks <number> --watch`. Move the task to review only when every check is
green; record PR URL/number, checked merged diff range, gate exits, and CI result.
Do not merge, version-bump, tag, or trigger `release.yml`.

## Phase B — lead integration and publish

The lead owns merge, main synchronization, version bump, annotated tag, pushes,
and release workflow monitoring. Any CI or release failure stops the sequence;
fixes return through a new PR before any retry tag because npm versions and tags
are immutable release coordinates.

## Release evidence

The final ledger must contain the PR URL, green CI run, merge SHA, release commit
SHA, tag target, release workflow URL/id and successful conclusion.
