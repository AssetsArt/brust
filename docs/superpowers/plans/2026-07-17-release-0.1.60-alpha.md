## Goal

Publish the reviewed imported-static-const native-inline fix as `brustjs` `0.1.60-alpha`, including all six native platform packages and `create-brustjs`.

## Authority and roles

- Aoki owns the release, integration, version bump, main tag, and final outcome.
- Dabin owns the exact pre-flight gate run and opening the PR from `feat/imported-static-const-native-inline-release` to `main`.
- Armin reviews the PR diff and release readiness if CI or scope evidence conflicts.
- Authority is in-loop. The human explicitly authorized publishing this release.

## Mandatory order

1. Run every pre-flight command from `.claude/skills/release/SKILL.md` on the feature branch.
2. Push `feat/imported-static-const-native-inline-release` and open a PR to `main`.
3. Wait for every required GitHub check to pass. Do not tag while the PR is open or red.
4. Merge using the repository's merge-commit convention and update local `main` with `--ff-only`.
5. On `main`, run `bun scripts/release-bump.ts 0.1.60-alpha`, verify all 15 refs, and commit `chore(release): 0.1.60-alpha`.
6. Create annotated tag `v0.1.60-alpha` on that main release commit. Push `main`, then push the tag.
7. Watch `release.yml` to success and verify the npm versions/dist-tags.

## Constraints

- Never tag the feature branch.
- Never bypass or race a red/pending `ci.yml` check.
- Use `scripts/release-bump.ts`; do not hand-edit version references.
- Do not amend or rewrite the reviewed implementation commits.
- If GitHub reports a failing check, record the exact run/log evidence before proposing any fix.

## Done when

- The main-bound PR is merged with green CI.
- `v0.1.60-alpha` points to the version-bump commit on `main`.
- `release.yml` succeeds for all platform builds and publish.
- npm exposes `brustjs@0.1.60-alpha` and `create-brustjs@0.1.60-alpha` under the expected alpha/latest tags.
