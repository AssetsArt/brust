# Wire error_414 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Send HTTP `414 URI Too Long` (with `Connection: close`) when an incoming request exceeds `MAX_REQUEST_BYTES = 16 * 1024` instead of silently closing the socket. The `error_414()` helper in `src/http.rs` is already declared but unreachable today.

**Architecture:** Change `read_full_request` from `bool` to a small `ReadOutcome` enum that distinguishes EOF / read-error / oversize. `handle_conn` emits a 414 on the oversize variant and closes the connection (rather than reusing keep-alive — a client that just blew the size cap is unlikely to recover). Other variants behave exactly as today.

**Tech Stack:** Rust 2024 edition, single-thread tokio / tokio-uring runtime, `bun test` for the integration check.

**Spec source:** `architecture.md` §HTTP layer mentions `read_full_request silently closes on over-cap; wiring 414 is a follow-up.` Handoff §"Sub-project candidates" line: `Wire error_414  ~½ d  Currently declared but unreachable — read_full_request silently closes on over-cap. Trivial fix.`

## Context

`src/server.rs:144-163` (`read_full_request`) returns a `bool`. `false` covers three different conditions:

1. Read error (`s.read_request` failed).
2. EOF before `\r\n\r\n` was seen (client closed cleanly without finishing a request, e.g. keep-alive idle close).
3. Buffer grew past `MAX_REQUEST_BYTES` without finding `\r\n\r\n`.

Cases 1 and 2 should keep doing what they do today — close the connection silently. Case 3 should now emit `HTTP/1.1 414 URI Too Long` and *then* close. The `error_414()` helper at `src/http.rs:63-65` already produces the exact bytes.

We do **not** want to keep-alive after 414 — the client's read pointer is somewhere mid-headers and the next bytes would be parsed as a new request. Returning the body and dropping the connection is the safe choice.

- [ ] **Step 1: Append a new `test()` block at the end of `tests/integration.test.ts`**

Open `tests/integration.test.ts`. After the existing `test('serves rendered html via worker pool', ...)` block (ends around line 33), append:

```typescript
test('returns 414 when request exceeds MAX_REQUEST_BYTES', async () => {
  const proc = spawn({
    cmd: ['bun', 'run', 'example/hello-world/index.ts'],
    env: {
      ...process.env,
      BRUST_PORT: '38124',
      RUST_LOG: 'brust=warn',
    },
    stdout: 'pipe',
    stderr: 'inherit',
  })

  const port = await readPortLine(proc.stdout)

  // Build a request whose request-line alone exceeds 16 KB.
  // 17 KB of path bytes guarantees we cross the cap before \r\n\r\n is seen.
  const longPath = '/' + 'a'.repeat(17 * 1024)
  const wire = `GET ${longPath} HTTP/1.1\r\nHost: 127.0.0.1\r\n\r\n`

  // We use a raw TCP socket because fetch() refuses to send a URL that long.
  const sock = await Bun.connect({
    hostname: '127.0.0.1',
    port,
    socket: {
      data() {},
      open() {},
      close() {},
      drain() {},
      error() {},
    },
  })

  sock.write(wire)
  // Give the server a moment to read, decide, write 414, and close.
  await new Promise((r) => setTimeout(r, 200))

  // Drain whatever the server sent.
  let received = ''
  const reader = (sock as any).readable?.getReader?.()
  if (reader) {
    while (true) {
      const { value, done } = await reader.read()
      if (done) break
      received += new TextDecoder().decode(value)
    }
  } else {
    // Fallback: Bun.connect returns a writable-only socket in some versions.
    // Use a plain TCP read via Node-style net if needed; for now, settle for
    // confirming the server didn't crash (the kill below) and the assertions
    // on the response will run when readable is present.
  }
  sock.end()

  // The server must have answered 414, not closed silently.
  expect(received).toContain('414')
  expect(received.toLowerCase()).toContain('uri too long')

  proc.kill('SIGINT')
  const exit = await proc.exited
  expect(exit).toBe(0)
}, 15_000)
```

### Task 3: Make `read_full_request` report why it returned

**Files:**
- Modify: `src/server.rs`

- [ ] **Step 1: Add the `ReadOutcome` enum**

Open `src/server.rs`. After the existing imports at the top (line 9, after `use crate::pool::WorkerPool;`), insert:

```rust
enum ReadOutcome {
    /// Headers complete (`\r\n\r\n` seen) — `buf` contains the full request.
    Complete,
    /// Read error or EOF before any complete headers — close silently.
    ClosedBeforeHeaders,
    /// Buffer grew past `MAX_REQUEST_BYTES` without seeing `\r\n\r\n`.
    Oversize,
}
```

Place the enum just above the `MAX_REQUEST_BYTES` constant block so it stays near the function that uses it.

- [ ] **Step 2: Rewrite `read_full_request` to return `ReadOutcome`**

Locate the existing function at `src/server.rs:144-163`:

```rust
async fn read_full_request(s: &mut TcpStream, buf: &mut Vec<u8>) -> bool {
    while buf.len() < MAX_REQUEST_BYTES {
        let n = match s.read_request(buf).await {
            Ok(n) => n,
            Err(e) => {
                warn!(error = %e, "read failed");
                return false;
            }
        };
        if n == 0 {
            return false; // EOF before complete request
        }
        // check for end-of-headers
        if buf.windows(4).any(|w| w == b"\r\n\r\n") {
            return true;
        }
    }
    // request too large
    false
}
```

Replace it with:

```rust
async fn read_full_request(s: &mut TcpStream, buf: &mut Vec<u8>) -> ReadOutcome {
    while buf.len() < MAX_REQUEST_BYTES {
        let n = match s.read_request(buf).await {
            Ok(n) => n,
            Err(e) => {
                warn!(error = %e, "read failed");
                return ReadOutcome::ClosedBeforeHeaders;
            }
        };
        if n == 0 {
            return ReadOutcome::ClosedBeforeHeaders;
        }
        if buf.windows(4).any(|w| w == b"\r\n\r\n") {
            return ReadOutcome::Complete;
        }
    }
    ReadOutcome::Oversize
}
```

The logic is identical, only the return type changed.

- [ ] **Step 3: Update the `handle_conn` call site**

In the same file, locate `src/server.rs:66-71`:

```rust
    loop {
        buf.clear();
        // EOF / read error / oversized request → silently close (client may have hung up cleanly).
        if !read_full_request(&mut s, &mut buf).await {
            return;
        }
```

Replace those six lines with:

```rust
    loop {
        buf.clear();
        match read_full_request(&mut s, &mut buf).await {
            ReadOutcome::Complete => {}
            ReadOutcome::ClosedBeforeHeaders => return,
            ReadOutcome::Oversize => {
                // Don't keep-alive: client's read cursor is mid-headers; the next
                // bytes on the wire would be misparsed as a new request.
                let _ = s.write_all(http::error_414()).await;
                return;
            }
        }
```

Leave the rest of `handle_conn` unchanged — the existing `parse_request`/method/path/`/ping`/pool path all run on the `Complete` branch.
