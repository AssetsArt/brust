## Method

Every row is a self-contained snippet compiled through `compileJsx` — the same napi entry point `runtime/cli/native-routes-emit.ts` uses for every native route — with component sources gathered by the CLI’s own `gatherComponentSources` import walk. Nothing is re-implemented or simulated.

Each construct is compiled in **two positions**, because they are not the same language:

1. **component file** — the construct is the default export of `Subject.tsx`, mounted by a trivial route (`<Subject/>`). This is the position the inliner is built around, and it is what the Status column measures.
2. **route file** — the exact same code written directly in the page component. The route function is lowered by a different path than an inlined component: its body must be a single `return <jsx>;`, and its module-level consts and same-file helpers are not resolved. The “Breaks in a route file” column reports that difference.

Status is read off the actual run:

- **INLINE** — no fallback warning and the row’s marker string is present in the emitted jinja. The construct becomes plain HTML: no React, no JS.
- **FALLBACK-BY-DESIGN** — the compiler declined to inline and that is the intended brust model. The component still renders (React SSR into a `comp_N` slot); it just does not hydrate. Interactivity is an `<Island>` or `export const behavior`.
- **GAP** — the construct does not inline (or inlines with different semantics) even though a static lowering is plausible. Every GAP is listed in the backlog at the bottom.

The “Observed” column reports what actually happened in the component position (`inlined`, `React SSR fallback`, `compile error`, `compiled, marker missing`), so a status never hides a surprise. `⚠` marks a result that disagrees with the expectation recorded in the battery.

## C. Hooks

Hooks imply a React runtime and client state. On a native route the component falls back to React SSR — markup renders, nothing hydrates. The brust answer is an `<Island>` (full React) or `export const behavior` (zero-React directives). These fallbacks are the model working as intended, not gaps.

| Pattern | Authoring | Status | Observed | In a route file | Compiler reason / note |
| --- | --- | --- | --- | --- | --- |
| <a id="c-usestate"></a>useState | `const [n] = useState(0)` | FALLBACK-BY-DESIGN | React SSR fallback | ❌ build error | `Subject`: component calls React hook `useState` — cannot inline — Client state — belongs in an Island or a `behavior` directive. |
| <a id="c-useeffect"></a>useEffect | `useEffect(() => {}, [])` | FALLBACK-BY-DESIGN | React SSR fallback | ❌ build error | `Subject`: component calls React hook `useEffect` — cannot inline — Effects run only in a browser; a native route ships no React to run them. |
| <a id="c-usememo"></a>useMemo | `const v = useMemo(() => label.toUpperCase(), [label])` | FALLBACK-BY-DESIGN | React SSR fallback | ❌ build error | `Subject`: component calls React hook `useMemo` — cannot inline — Memoisation has no meaning in a static template — though the derived value itself is often statically computable. |
| <a id="c-usecallback"></a>useCallback | `const onClick = useCallback(() => {}, [])` | FALLBACK-BY-DESIGN | React SSR fallback | ❌ build error | `Subject`: component calls React hook `useCallback` — cannot inline — Event handlers are client behaviour — Island or `behavior`. |
| <a id="c-useref"></a>useRef | `const ref = useRef(null)` | FALLBACK-BY-DESIGN | React SSR fallback | ❌ build error | `Subject`: component calls React hook `useRef` — cannot inline — A ref is a handle to a live DOM node owned by React. |
| <a id="c-usecontext"></a>useContext | `const tone = useContext(ToneContext)` | FALLBACK-BY-DESIGN | React SSR fallback | ❌ build error | `Subject`: component calls React hook `useContext` — cannot inline — Context is resolved by the React renderer; a static template has no provider tree. |
| <a id="c-custom-hook"></a>custom hook | `const tone = useTone()` | FALLBACK-BY-DESIGN | React SSR fallback | ❌ build error | `Subject`: component calls React hook `useTone` — cannot inline — Detected by the `use*` naming convention — even a pure custom hook (no React hook inside) falls back. |

## E. React 19 specifics

Features that only exist in React 19. Some are pure markup (document metadata); the rest are client/server-runtime features a zero-JS template cannot express.

| Pattern | Authoring | Status | Observed | In a route file | Compiler reason / note |
| --- | --- | --- | --- | --- | --- |
| <a id="e-document-metadata"></a>document metadata hoisting (`<title>` / `<meta>` inside a component) | `<title>Docs</title><meta name="description" …/>` | GAP | inlined | ✅ inlines | the tags stay where they were written instead of being hoisted into `<head>` — React 19 hoists `<title>`/`<meta>`/`<link>` rendered anywhere in the tree into `<head>`. | <a id="e-ref-cleanup"></a>ref callback returning a cleanup fn | `ref={(el) => { …; return () => {} }}` | FALLBACK-BY-DESIGN | React SSR fallback | ❌ build error | `Subject`: `ref` attribute not supported — A ref callback runs in the browser against a live node — client-only by construction; `behavior` is the zero-React equivalent. |
| <a id="e-use-action-state"></a>useActionState | `const [state, action] = useActionState(fn, "")` | FALLBACK-BY-DESIGN | React SSR fallback | ❌ build error | `Subject`: component calls React hook `useActionState` — cannot inline — React 19 form actions need the React runtime for the pending/optimistic transition; native routes use brust’s own `defineActions` + a plain form post. |
| <a id="e-use-optimistic"></a>useOptimistic | `const [shown] = useOptimistic(label)` | FALLBACK-BY-DESIGN | React SSR fallback | ❌ build error | `Subject`: component calls React hook `useOptimistic` — cannot inline — Optimistic UI is client state by definition. |

### Route-file-only gaps

10 construct(s) that inline perfectly from a component file but fail when written directly in the route component. This asymmetry is one gap class, not 10: the route function is lowered without the module-level const table, the same-file helper table, and the multi-statement body the inline path already supports. Closing it is the single highest-leverage item in this report — until then “move it into its own component” is the workaround for all of them.
