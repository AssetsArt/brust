## Summary

**Units.** Client JS = the gzip size of the client JS the page loads (the runtime core, the feature modules the page preloads `rt-*`, the chunk of each island and native component it reaches, and the shared chunks those import; the chunk of a React child of an island is not loaded, the island renders it), rounded to the nearest 1 KiB (a non-zero size never shows 0); a page with no island and no native chunk loads no JS and shows exactly `0`. Exact raw and gzip bytes per page go to `tests/fixtures/shadcn/.rows/shadcn-sizes.json` on every run (not committed; CI uploads it as an artifact). Byte regressions are guarded by the runtime-split budget, not by this file.

## Classification

Every blocker above is **survey truth** (the compiler or build behaves so on shadcn's own code) or a **census** hit (a construct found in library code); **fixture mistakes: none found** (37 survey truth, 15 census). The fixture is the CLI output unedited (the `@/` imports resolve through its `tsconfig.json` `paths`), and it uses a plain `brust build <entry>` with `[css] global` only: no build option, no pin, no config that could cause a blocker.

### History: the named-export build rule (S0 → S1.1, PR #198)

The first survey (S0) found that 63 of 64 whole-page builds failed, and it was not a fixture problem: a React-tier component is built as an island whose entry was `import Comp from "<its file>"` (`componentImport`, packages/brust/src/build/bundle.ts), while shadcn files export every component **by name** (`Card`, `CardHeader`, …), so one React shadcn component made the bundler fail with `No matching export in "<file>" for import "default"`. There is no diagnostic code for that kind of failure (a build error, hiding every other row of the page). S1.1 (PR #198) made named-export islands build; the minimal repro below stays as the guard (`bun test scripts/shadcn` fails if the named variant stops building):

| Variant | Component | Fallback codes | `brust build` |
|---|---|---|---|
| named | `export function Box({ className, ...props })` in ui.tsx, used by a page | — | ok |
| default | the same component as `export default function Box` | — | ok |
| static | `export function Box({ className })` (no rest props: static, inlined) | — | ok |

## Method and limits

- **Fixture.** `tests/fixtures/shadcn`: `components/ui/*` and `hooks/` are exactly what `shadcn add` wrote at the pinned version, imports included: the CLI imports siblings as `@/components/ui/x` (a tsconfig `paths` alias) and the compiler resolves it from the fixture's `tsconfig.json` (R34.76; until then the 26 sibling/hook imports had to be rewritten to relative paths). This registry version imports `cn` from the npm package `cn`, so the CLI writes no `lib/utils.ts`.
- **Rows.** `pages/<name>.tsx` is one page per component, written the way shadcn's own examples use it, plus `badge-aslink`, `button-aschild` (`asChild` + Slot) and `button-alias`. Each page is also built alone (`brust build`, entry generated under `.rows/`), because one failing page would otherwise fail the build of all.
- **Islands.** Walk down from the page root through static and native components; every React component met is one island.
- **Worker.** The job calls the server plans for one request, read from the manifest the way brust-core plans them: the page component's own jobs (an island's SSR render is one) plus one per child record whose component has a job or `useId` values (a per-row record counts once). `0` = Rust answers the page alone. Since F149 the build runs a child's class job (`cn`, `clsx`, `tailwind-merge`, `class-variance-authority`) once when every input is a constant, so such an instance has no record. `brust start` still starts its worker pool whatever the manifest says (F165).
- **Library source.** The library tables are an analysis (each exported component probed alone). Since F153c the build follows a package import into the package's own source when its source map carries it (`sourcesContent`) and it matches the published JS (literals and names, checked at build); the source is written under `.brust/pkg-src`, compiled like app code, and anything that needs React keeps the island of the published export, with the reason in its `external-component` message. Minified published code cannot be split into components; those packages get the whole-package construct census only.
- **Radix `Primitive`.** `@radix-ui/react-primitive` makes its components with a factory (`NODES.reduce(…)`); the compiler recognises that exact shape and renders `Primitive.<tag>` as the element `<tag>`, `asChild` resolved at the call site. The factory also sets `window[Symbol.for('radix-ui')] = true` on every render; a compiled page does not: in the installed tree nothing reads it (only `@radix-ui/react-primitive` and bundles of it write it).
- **Construct census.** Regex over each declaration after Bun lowers TSX/JSX to calls. It names the construct, not whether the component is otherwise supportable. "Blocks today" follows the hook/API table of docs/react-coverage.md.
- **Not covered here.** Transitive non-Radix dependencies (react-remove-scroll, floating-ui, aria-hidden), lucide icons (one row per icon would add nothing: the compiler inlines them, L23), CSS output (the Tailwind compiler lane owns it) and runtime behaviour (R34.3 proves that per lane).
