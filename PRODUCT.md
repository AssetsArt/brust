# Product

## Register

brand

## Users
Developers who build web apps with React and care about what reaches the browser: people evaluating brust for a new project, and people already on brust looking up how a feature works. They arrive from GitHub or npm, often mid-task, with an editor open beside the browser. Many read English documentation as a second language; the team behind brust is Thai.

## Product Purpose
The brust documentation site (`website/`, built with brust itself on the workspace `@brust/core`). The landing page shows in one scroll what brust is: React compiled ahead of time, served by Rust, most pages shipping no client JavaScript. The docs teach it step by step, code first. Success: a visitor runs the quickstart within a minute and understands the three rendering tiers without reading an essay.

## Brand Personality
Futuristic, warm, confident. A near-future workshop: precise engineering presented with warmth instead of chrome. Claims are shown, not asserted: real commands, real output, real measurements. Reference vibe: impeccable.style/neo-mirai (warm paper ground, gold and sun-orange, deep teal night bands, Chakra Petch display, a serif text face, mono labels, sun-disc geometry, bilingual taglines).

## Anti-references
- Comparisons against other frameworks: no "vs Next.js" tables, no "Nx faster" multipliers.
- The generic SaaS template: purple-blue gradients, identical icon-card grids, marketing hero metrics with no method behind them.
- Stock documentation themes (Docusaurus/VitePress defaults): grey, flat, interchangeable.
- Dark modes that glare: pure black with saturated accents.

## Design Principles
1. Show the machine working: every claim sits next to the code or the output that proves it.
2. Code first, prose second: one short sentence, then the thing you can copy.
3. Warm precision: technical exactness carried by a warm, human palette and type.
4. One idea per step: sequences are numbered only when the order is real.
5. Honest numbers: measurements carry their method, date and machine.

## Accessibility & Inclusion
WCAG 2.2 AA: text contrast at least 4.5:1 (3:1 for large text), full keyboard use with visible focus, every animation has a reduced-motion alternative. Thai must read well: every text face falls back to a Thai-capable face of the same character (Chakra Petch covers Thai for display; the serif text face falls back to Noto Serif Thai), so Thai docs can follow without a redesign.
